## Part B: Lecture code transfer

### 1. Today's Challenge

Title: Count out-of-order mission events.

Implement `count_out_of_order(timestamps)`. Count pairs of positions `i < j` for which `timestamps[i] > timestamps[j]`. Equal timestamps are not reversed. Return an integer and leave the input unchanged.

Constraints: 0–100,000 integer timestamps, each between -1,000,000,000 and 1,000,000,000. Use O(n log n) time and O(n) extra space. Do not enumerate every pair in the implementation.

| Input | Output |
| --- | --- |
| `[2, 4, 1, 3, 5]` | `3` |
| `[2, 2, 1]` | `2` |
| `[]` | `0` |

Lecture concept transferred: divide the input, solve smaller problems, and merge sorted results. The additional result is a pair count, rather than just a sorted list.

### 2. My Initial Approach Before AI Help

No pre-assistance version was saved. A direct approach checks all `i < j` pairs, but that needs O(n²) time. The working approach counts pairs within each half recursively and counts pairs crossing the split during the merge.

### 3. AI Tutor Help

Reasoning check: when `right[j] < left[i]`, how many left-side values are still unmerged? Because the left half is sorted, every one of them contributes a reversed pair with `right[j]`.

### 4. My Revision

Design correction: take the left value on equality and increase the count only on a strict reversal. Keep a separate merged list to preserve the original input.

### 5. Verification

#### Final implementation

```python
def count_out_of_order(timestamps):
    """Count pairs i < j with timestamps[i] > timestamps[j], without mutation."""
    def sort_and_count(values):
        if len(values) < 2:
            return values[:], 0

        middle = len(values) // 2
        left, left_count = sort_and_count(values[:middle])
        right, right_count = sort_and_count(values[middle:])
        merged = []
        count = left_count + right_count
        i = j = 0

        while i < len(left) and j < len(right):
            if left[i] <= right[j]:
                merged.append(left[i])
                i += 1
            else:
                merged.append(right[j])
                count += len(left) - i
                j += 1

        merged.extend(left[i:])
        merged.extend(right[j:])
        return merged, count

    return sort_and_count(timestamps)[1]
```

### 6. One-Minute Reflection

Why it works: every pair lies inside the left half, inside the right half, or crosses the split. Recursion counts the first two categories. The merge counts each crossing pair exactly when its right-hand element is taken. These categories are disjoint.

Complexity: O(n log n) time, O(n) peak auxiliary storage, and O(log n) recursion depth. Each recursion level performs linear merging work. The list slices add linear work per level without changing the bound.

What I understand better: sorted order can help count relationships without listing them. I would still want to compare this approach with an iterative merge to understand the recursion and allocation costs.
