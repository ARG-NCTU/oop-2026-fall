### ① Check My Understanding

Answers revised after AI hints: not recorded.

1. Statement: Halving a sorted search interval each iteration gives logarithmic worst-case search time when each iteration does constant work.

   Answer: True. After k halvings, the candidate count is about n / 2^k. Reaching a constant-sized interval takes O(log n) iterations.

2. Statement: Copying half of a Python list at every bisection step always preserves O(log n) total time.

   Answer: False. Slices copy elements. The copied lengths can total n/2 + n/4 + ... = O(n), even though the recursion depth is logarithmic. Index bounds avoid these copies.

3. Statement: The lecture's subset generator can return all subsets of an n-element input in polynomial total time.

   Answer: False. It returns 2^n subsets. Materializing lists also copies their contents. For distinct elements, the total number of element occurrences across those lists is n * 2^(n-1) for n >= 1.

4. Statement: The lecture's recursive index-based bisection search uses O(1) auxiliary space because it does not slice the input.

   Answer: False. Its recursive call stack can have O(log n) frames. An iterative implementation can keep only its current bounds and use O(1) auxiliary space.

5. Statement: The lecture's bisection algorithm remains correct if the input is unsorted.

   Answer: False. Discarding half the candidates depends on sorted order. For example, searching for 9 in [9, 1, 5] can discard its position after inspecting the middle value.

### 1. Today's Challenge

Core concept: Use index-based bisection to find boundaries in a sorted sequence. The lecture's `bisect_search2` motivates maintaining bounds rather than copying slices. This exercise uses two boundary searches to answer a counting query.

Implement `count_events(timestamps, start, end)` for an already sorted mission log. Return how many events fall in the half-open window `start <= timestamp < end`. Duplicate timestamps represent separate events. Equal or reversed bounds return zero. Leave the input unchanged.

Input: A nondecreasing list of integer timestamps and two integer bounds.

Output: One integer count.

Constraints:

- 0 <= number of timestamps <= 100,000.
- Timestamps and bounds are integers between -1,000,000,000 and 1,000,000,000.
- Sorted order is a precondition. Do not sort or validate the entire input inside each query.
- Use O(log n) time for nonempty input and O(1) auxiliary space.
- Do not slice, scan the input, or use a library bisection function in the implementation.

### 6. One-Minute Reflection

Why it works: During each boundary search, every position before `low` has a value below the target and every position at or after `high` has a value at least the target. The unknown interval is `[low, high)`. Each comparison preserves those facts and strictly shrinks that interval. At termination, `low == high` is the first qualifying index, or the list length if none qualifies. Subtracting the two boundary indices counts exactly the events in the requested window. Empty and reversed windows return zero immediately.

Time complexity: Each search halves its unknown interval and uses one indexed comparison per iteration. Two searches take O(log n) time for n >= 2, with constant work for smaller inputs. Integers have bounded size under the stated constraints. Auxiliary space is O(1), and no list is copied. Sorting or checking sorted order would add work, so sortedness remains an explicit precondition.

Takeaway: A count query can use boundary positions without enumerating all matching events. Two logarithmic searches still take logarithmic time.
