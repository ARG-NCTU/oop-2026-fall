### 1. Today's Challenge

Title: Minimum cost to meet an upgrade target.

Implement `min_upgrade_cost(options, target)`. Each option is `(cost, gain)` and can be chosen at most once. Return the smallest total cost whose combined gain is at least the target. Overshooting is allowed. Return `None` if the target is unreachable and `0` if the target is zero. Preserve the input.

Constraints: 0–100 options; positive integer costs from 1 through 10,000; positive integer gains from 1 through 1,000; integer target from 0 through 1,000. Identical entries represent separate available upgrades. Use memoized recursion with an index and remaining target.

| Options | Target | Output |
| --- | --- | --- |
| `[(5, 8), (4, 5), (4, 5)]` | `10` | `8` |
| `[(9, 20)]` | `10` | `9` |
| `[(3, 4)]` | `8` | `None` |

### 6. One-Minute Reflection

Why it works: any valid subset either contains the current option or excludes it. The recurrence considers both categories and chooses the cheaper reachable result. Once the remaining target is nonpositive, taking nothing more costs zero. Positive costs make further selections unnecessary. The index strictly increases, establishing termination.

Complexity: O(nT) time and memo space for positive target T, plus O(n) call-stack space. Each state does constant work under the bounded integers. Target zero returns immediately. The bound is pseudo-polynomial.
