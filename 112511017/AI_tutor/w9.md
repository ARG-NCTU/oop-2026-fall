### 5. Verification

#### Final implementation

```python
def greedy_inspections(jobs, budget):
    """Select jobs by descending value/time, preserving input order on ties."""
    ranked = sorted(range(len(jobs)), key=lambda i: jobs[i][1] / jobs[i][0],
                    reverse=True)
    chosen = []
    used = total = 0
    for index in ranked:
        duration, value = jobs[index]
        if used + duration <= budget:
            chosen.append(index)
            used += duration
            total += value
    return chosen, total
```

### 6. One-Minute Reflection

Why it works: sorting produces the required priority order. Each acceptance keeps used time within the budget, and each index is considered once. Stable sorting preserves input order for equal keys. The accumulated value is exactly the sum of accepted jobs.

Complexity: O(n log n) worst-case time and O(n) extra space for the ranking and output. The selection scan is O(n). Integer bounds keep the ratio comparisons well separated at ordinary double precision.

What I understand better: a heuristic can be useful and correctly implemented without guaranteeing the global optimum. The next question is how to find the exact answer when input sizes permit a more expensive search.
