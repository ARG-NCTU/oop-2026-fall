## Part B: LeetCode-style Lecture Code Transfer

### 1. Today's Challenge

Core concept from today's OCW lecture: 依選擇規則排序、貪婪選擇、逐步檢查限制、區分可行與最佳，並分析演算法效率。

AI-generated coding challenge title: 單一場地的活動排程。

Problem statement: 一個場地收到多個活動申請，每個活動以 [開始時間, 結束時間] 表示。活動不可切割、每個最多選一次，同一時間只能舉辦一個活動。回傳最多能舉辦的活動數量。上一場結束時間可以等於下一場開始時間；允許不選活動。本題要求保證最佳，目標為活動數量，不是總時長。

Input: 未排序的整數二元串列 intervals。

Output: 整數，為最大可安排活動數量。

Constraints:

- 0 <= len(intervals) <= 10^4。
- 每個活動滿足 0 <= start < end <= 10^6。

| Input | Output | Explanation |
| --- | --- | --- |
| [[1,4], [2,3], [3,5], [5,6]] | 3 | 安排 [2,3]、[3,5]、[5,6]。 |
| [[1,5], [2,6], [3,7]] | 1 | 任兩場皆重疊。 |
| [] | 0 | 沒有活動。 |

### 2. My Initial Approach — Before AI Help

My approach: 我原本想判斷可行組合，再找總時長最長的安排。在 AI 提示後，修正為找出包含最多活動的合法組合。之後嘗試「開始時間最早」及「持續時間最短」的貪婪規則。

若完整列舉並比較所有可行組合，可以取得最佳解，但 n 個活動有 2^n 個子集合，不適合本題最多 10,000 個活動的規模。

### 3. AI Tutor Help

Did you ask the AI Tutor for help? Yes — 接受反例提示。

The most useful hint/question from AI was: 如果先選最早開始或持續最短的活動，是否可能擋住其他兩場可以連續舉辦的活動？

It helped me realize that: 貪婪規則看似合理，仍需反例測試或正確性證明，不能只憑直覺認定能得到最佳解。

反例一（開始最早不保證最佳）：[[1,10], [2,3], [3,4], [4,5]]。先拿 [1,10] 只能安排 1 場，其他三場則能連續安排，共 3 場。

反例二（持續最短不保證最佳）：A=[0,3]、B=[2,4]、C=[3,6]。B 最短，但它和 A、C 都重疊，先選 B 只能安排 1 場。A 與 C 可相接，能安排 2 場。

### 4. My Revision

Did you change your approach or code after interacting with AI? Yes。

What did you change, and why? 我先把「總時長最長」改成「活動數量最多」。依結束時間由小到大排序，每次選擇與已選活動不衝突、且最早結束的下一場，為後續活動保留最多可用時間。

程式使用 sorted 與 key 函式，對應講義中以不同 keyFunction 排序、形成不同貪婪策略的模式。限制檢查從背包的總成本上限，轉移為活動時間不能重疊。

### 6. Why the Solution Works

每次只選 start >= last_end 的活動，所以結果一定不重疊。

考慮任一最佳排程的第一場活動 O，以及全部候選中最早結束的活動 G。G 的結束時間不晚於 O。用 G 替換 O 後，後續原本能接在 O 後面的活動，也都能接在 G 後面，因此活動數量不減，且仍然合法。這表示至少存在一個最佳排程以 G 開頭。

選定 G 後，把相同論點用在剩下可接續的活動上，反覆進行即可得到最大活動數。結束時間相同時，任選其中一個可行活動皆不影響這個保證。

這個證明適用於本題所有活動價值相同、目標是最大場次的設定。如果改成每場有不同收益、要最大化總收益，不能直接沿用這個最佳性保證。

### 7. Time and Space Complexity

排序花 O(n log n)，掃描花 O(n)，總時間為 O(n log n)。額外空間為 O(n)，因 sorted 會產生新串列，排序也可能使用額外工作空間。輸入不會被修改。
