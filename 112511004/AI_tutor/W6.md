### ② My Misconception

**Before: I thought…**

我曾把 n=1 代入 Big O，寫成 O(n)=O(n²)=O(1)，並用這個寫法比較演算法在這個輸入上的實際操作次數。

**Now: I understand…**

Big O 描述工作量隨輸入規模增加時的漸近上界。比較某個固定輸入時，應代入實際操作次數，而不是把 Big O 當成操作次數。第 3 題在 n=1 時，A 是 100 次、B 是 1 次，足以推翻「A 對所有 n 都較少」。當 n>100 時，才是 100n<n²；n=100 時相等。

## Part B: LeetCode-style Lecture Code Transfer

### 1. Today’s Challenge

**Core concept from today’s OCW lecture:**

使用巢狀迴圈逐一比較元素、找到符合條件的元素後提早結束內層搜尋，以及分析最壞情況的時間複雜度。

**AI-generated coding challenge title:** 找出有時間衝突的活動（Find Conflicting Events）。

### Problem Statement

你收到一份活動清單 events。第 i 個活動以 [start_i, end_i] 表示，代表它從 start_i 開始，在 end_i 結束。

活動時間採半開區間 [start_i, end_i)：開始時刻包含在活動內，結束時刻不包含。例如 [1, 3) 與 [3, 5) 可以接續進行，不算衝突。

請回傳所有「至少與另一個活動有時間重疊」的活動索引，索引由小到大排列，每個索引只出現一次。活動不得與自己比較。即使兩筆活動時間完全相同，仍視為兩個不同活動。

使用已學過的串列、迴圈、條件判斷與數值比較完成；不需排序、集合或額外套件。

### Input / Output Specification

- 輸入：events，是由二元素串列構成的串列；輸入順序不保證依時間排序。
- 輸出：有衝突活動的索引串列，使用從 0 開始的索引，依索引遞增排列。
- 函式介面：conflicting_events(events)。

### Constraints

- 0 ≤ len(events) ≤ 1000。
- 每筆活動都有兩個整數，且 0 ≤ start_i < end_i ≤ 1,000,000。
- 可以有重複的活動時間。
- 不可修改輸入串列。

### Examples

**Example 1**

```text
Input:  [[9, 11], [10, 12], [12, 13], [14, 16]]
Output: [0, 1]
```

活動 0 與 1 在 [10, 11) 重疊。活動 1 在 12 結束、活動 2 在 12 開始，兩者不衝突。

**Example 2**

```text
Input:  [[1, 2], [2, 3], [3, 4]]
Output: []
```

活動都只是端點相接，沒有重疊。

**Example 3**

```text
Input:  [[1, 10], [2, 3], [4, 5]]
Output: [0, 1, 2]
```

活動 0 包含活動 1 和 2 的時間，因此三個活動都至少有一個衝突對象。

### 2. My Initial Approach — Before AI Help

對每個活動 i，逐一檢查其他活動 j。跳過 i=j；如果找到任一重疊活動，就把 i 加入答案並結束這次內層搜尋，再處理下一個 i。若沒有找到，則不加入 i。

這裡轉移的是講義「對外層每個元素進行內層搜尋」的模式。新的判斷條件是時間區間重疊，而非元素相等；輸出則是每個具有衝突的活動索引。

**The most useful hint/question from AI was:**

兩個活動沒有衝突，是否代表其中一個活動在另一個開始前就已結束？端點剛好相等應如何處理？

**It helped me realize that:**

兩個半開區間 i、j 不重疊，表示 end_i ≤ start_j，或 end_j ≤ start_i。因此重疊的條件是：

```text
start_i < end_j AND start_j < end_i
```

必須使用嚴格小於，才不會把端點相接誤判為衝突。

### 4. My Revision

- 排除 i=j，避免每個活動都因與自己重疊而被判定衝突。
- 使用嚴格小於，排除端點相接。
- 找到一個衝突對象後 break，避免同一索引被重複加入。
- 外層依索引遞增處理，讓結果自然保持順序。

### Final Program 

```python
def conflicting_events(events):
    result = []

    for i in range(len(events)):
        for j in range(len(events)):
            if i == j:
                continue

            start_i, end_i = events[i]
            start_j, end_j = events[j]

            if start_i < end_j and start_j < end_i:
                result.append(i)
                break

    return result
```

### Why the Solution Works

對任何活動 i，內層會檢查所有其他活動，直到找到衝突對象，或全部檢查完。

- 如果把 i 加入結果，一定是存在另一個 j 滿足重疊條件，因此不會把沒有衝突的活動誤加入。
- 如果 i 與任何其他活動重疊，內層最終會遇到衝突對象並加入 i，因此不會漏掉應加入的活動。
- 加入 i 後立即 break，確保同一索引只出現一次。
- 外層由小到大處理索引，確保輸出順序符合要求。

### Complexity

令 n = len(events)。每筆活動由兩個整數構成，數值比較與索引存取採課堂固定成本模型。

- 最壞時間複雜度：**O(n²)**。當所有活動都不重疊，每個活動都必須搜尋其他 n−1 個活動，共 n(n−1) 次有效的區間比較；即使有 break，這種輸入仍不會提早停止。
- 包含回傳結果的額外空間：**O(n)**，結果最多儲存 n 個索引。
- 若不計回傳結果，輔助空間：**O(1)**，只使用固定數量的索引與暫存變數。
