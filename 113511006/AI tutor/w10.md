## Part B: LeetCode-style Lecture Code Transfer

### 1. Today's Challenge

Core concept: Optimal substructure and bottom-up dynamic programming.  
Challenge title: Minimum Coins for Exact Payment

Problem: Given positive coin denominations and a nonnegative target amount, return the smallest number of coins needed to make the exact amount. Each denomination can be used any number of times. Return `-1` if no combination works.

Example: `coins=[1,3,4]`, `amount=6` gives `2`.

### 2. My Initial Approach — Before AI Help

I first considered taking the largest possible coin repeatedly. After checking the example above, I recognized that I needed to evaluate combinations rather than commit to one local choice.

### 3. AI Tutor Help

Did I use AI help? Yes — to review the recurrence and tests.

Most useful idea: Define `dp[x]` as the minimum number of coins needed for exactly `x`, and update it using `dp[x-coin] + 1` for every usable denomination.

What I learned: A precise state definition makes the DP transition easy to explain and prevents accidental use of a result that is not an exact payment.

### 4. My Revision

I used tabulation with `dp[0] = 0` and a value larger than any valid answer to represent unreachable states. For every target amount, I tried all coin denominations and took the minimum. At the end, an unreachable state becomes `-1`.
