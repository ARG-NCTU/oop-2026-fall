## Part B: LeetCode-style Lecture Code Transfer

### 1. Today's Challenge

Core concept: Representing a maze as a graph, BFS, and parent-based path reconstruction.  
Challenge title: Shortest Route Through a Grid Maze

Problem: A grid contains open cells `.` and walls `#`. Starting from one coordinate, move up, down, left, or right to reach a goal. Return the shortest path as a list of `(row,column)` coordinates, including both endpoints. If unreachable, return an empty list.

### 2. My Initial Approach — Before AI Help

I treated each open cell as a graph node and valid adjacent cells as edges. BFS seemed appropriate because each movement costs exactly one step.

### 3. AI Tutor Help

Did I use AI help? Yes — to review path reconstruction and edge cases.

Most useful question: “When the goal is reached, how will the program know which cells formed the route?”

What I learned: It is not enough to track visited cells. Saving the parent at first discovery preserves a shortest route that can be rebuilt backward.

### 4. My Revision

I used `deque` as a queue and a dictionary that serves as both the visited set and parent mapping. When the goal is removed from the queue, I follow parent links backward, then reverse the resulting list. I also return `[]` for blocked, missing, or unreachable endpoints.

### 5. Verification

Final code: `weekly_code/w11.py`  
Status: Passed four assertion-based tests.

| Case | Expected | Actual |
| --- | --- | --- |
| Three-row maze with one route around walls | Seven coordinates, from `(0,0)` to `(2,0)` | Same seven-coordinate path |

| Start equals goal on open cell | `[(0,0)]` | `[(0,0)]` |

Complexity: O(R × C) time and O(R × C) space for an R-by-C grid.
