### 題目與解答

#### 第 1 題：二分搜尋的前提

**題目：** 二分搜尋可以用在任何 list 上，不需要先排序。

**答案：錯。**

二分搜尋每次看正中間的元素，再根據「比目標大還是小」丟掉一半。這個判斷成立的前提是 list 已經由小到大排好：中間的數比目標大，目標才一定在左半邊。如果 list 沒有排序，看到中間的數也無法判斷目標在哪一邊，丟掉一半就可能把答案丟掉。所以未排序的 list 只能用線性搜尋，是 O(n)；排好序之後才能用二分搜尋降到 O(log n)。

#### 第 2 題：會複製 list 的二分搜尋

**題目：** 課堂的 `bisect_search1` 每次遞迴都把搜尋範圍砍一半，所以它的複雜度是 O(log n)。

**答案：錯。**

遞迴呼叫的次數確實只有約 log n 次，但 `bisect_search1` 每次都用 `L[:half]` 或 `L[half:]` 把一半的 list 複製出來，再傳給下一層。複製一個長度 k 的 list 需要 O(k) 的時間，所以每次呼叫自己做的事並不是 O(1)。把每層複製的長度加起來是 n/2 + n/4 + n/8 + …，總和約為 n，因此整體由複製主導，是 O(n)。課堂接著寫出 `bisect_search2`，不複製 list，而是用 `low`、`high` 兩個位置記住目前的搜尋範圍，每次呼叫只做 O(1) 的事，總共 log n 次，才是真正的 O(log n)。

#### 第 3 題：`int_to_str` 的複雜度

**題目：** `int_to_str(i)` 用迴圈把整數一位一位轉成字串，每次 `i = i // 10`，所以它的複雜度是 O(log n)。

**答案：對。**

迴圈每一輪用 `i % 10` 取出個位數，再用 `i // 10` 拿掉個位數，所以迴圈跑的次數等於 i 的位數。i 每多一位數，數值就大約變成 10 倍，但迴圈只多跑一次；反過來說，迴圈次數是 log₁₀ i。每一輪做的事（取餘數、查字元、接字串、整數除法）都是固定的步數，所以整體是 O(log n)。這跟二分搜尋「每次砍一半」是同一類，只是每次縮小成十分之一。

#### 第 4 題：列出所有子集合

**題目：** 列出一個 list 所有子集合的程式（課堂的 `gen_subsets`）之所以是 O(2ⁿ)，是因為寫法不好；只要改寫得更聰明，就能降到 O(n²) 之類的多項式時間。

**答案：錯。**

每個元素都只有「選」或「不選」兩種可能，所以 n 個元素的 list 共有 2ⁿ 個子集合。題目要求把它們全部列出來，光是輸出答案本身就有 2ⁿ 個 list，至少需要 2ⁿ 步，任何寫法都不可能比這更快。課堂的 `gen_subsets` 先遞迴求出不含最後一個元素的所有子集合，再把每一個都加上最後一個元素，數量每多一個元素就翻倍，這是問題本身的難度，不是程式寫得不好。

#### 第 5 題：遞迴費氏數列

**題目：** 遞迴版的費氏數列 `fib(n) = fib(n-1) + fib(n-2)` 很慢，主要原因是同樣的 `fib(k)` 被重複計算了很多次；如果用字典記住算過的結果，就能把複雜度降到 O(n)。

**答案：對。**

`fib(n)` 每次會呼叫自己兩次，呼叫樹一層一層分岔，總呼叫次數大約隨 n 指數成長，是 O(2ⁿ)。畫出 `fib(5)` 的呼叫樹就會看到 `fib(3)` 被算了 2 次、`fib(2)` 被算了 3 次，n 越大重複越嚴重。跟子集合不同，費氏數列的答案只是一個數字，慢只是因為重算。Lecture 6 教過的做法是用字典記住算過的 `fib(k)`，下次直接查（查 key 是 O(1)），每個 `fib(k)` 只真正計算一次，總共 n 次，複雜度降為 O(n)。

### ② My Misconception

- **Before（常見誤解）：** 以為只要演算法「每次砍一半」就一定是 O(log n)；也以為所有 O(2ⁿ) 的程式都只是寫得不夠好，換個寫法就能變快。
- **Now（觀念整理）：** 遞迴的複雜度要算「呼叫幾次 × 每次呼叫自己做多少事」，`bisect_search1` 雖然只呼叫 log n 次，但每次複製 list 是 O(n)，整體就不是 O(log n)。另外要分清楚兩種指數複雜度：列出所有子集合是答案本身就有 2ⁿ 個，無法更快；遞迴費氏數列則是因為重複計算，用字典記住就能降到 O(n)。

### ③ Challenge the AI

- **Question examined：** 第 2 題，`bisect_search1` 的複雜度。
- **Why：** Technically questionable。
- **Brief explanation：** 標準答案說 `bisect_search1` 是 O(n)，但這需要仔細把每層複製的長度相加（n/2 + n/4 + … ≈ n）才得到。如果用比較粗略的估計——log n 次呼叫、每次複製最多 O(n)——會得到 O(n log n)。這兩個答案都說明了「它不是 O(log n)」，所以題目的「錯」沒有問題；但如果題目改問「它的複雜度是多少」，O(n) 和 O(n log n) 就會因為估計得多細而有不同答案，容易造成混淆。題目應該說明是要求精確的上界，還是只要判斷「是不是 O(log n)」。
