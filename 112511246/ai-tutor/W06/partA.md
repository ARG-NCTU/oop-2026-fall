### 題目與解答

#### 第 1 題：O(1) 的意義

**題目：** O(1) 的意思是：這個函式只執行 1 個步驟。

**答案：錯。**

O(1) 表示步數是固定的常數，不會隨輸入大小 n 改變，而不是「只有 1 步」。課堂的 `c_to_f(c)` 計算 `c * 9 / 5 + 32`，有乘、除、加 3 個運算，不管 c 是 10 還是一百萬都是 3 步，所以是 O(1)。就算一個函式固定做 1000 步，只要這個數字跟 n 無關，依然是 O(1)；Big O 會把常數倍數拿掉，3 和 1000 都化簡成 1。

#### 第 2 題：用秒數比較演算法

**題目：** 比較兩個演算法誰比較快，最準確的方法是在同一台電腦上各跑一次，看誰花的秒數少。

**答案：錯。**

課堂一開始就試了計時的方法，並指出它的問題：執行時間會隨電腦而不同，在同一台電腦上每次跑也會因為背景程式等因素而變動，實作細節不同時間也會不同；而且跑一次只能看到某一個輸入大小的結果，看不出輸入變大時時間怎麼成長。課堂接著改用「數基本運算的次數」，再進一步用 order of growth（Big O）描述「輸入變大時，步數成長得多快」，這樣才能比較演算法本身，而不受機器影響。

#### 第 3 題：化簡成 Big O

**題目：** 一個函式的步數是 `n² + 1000n + 5`，它的 Big O 是 O(n²)。

**答案：對。**

化簡 Big O 有兩條規則：只留下成長最快的那一項，並拿掉前面的常數倍數。`5` 是常數，`1000n` 在 n 小的時候雖然比 n² 大，但 n 超過 1000 之後就會被 n² 超越，Big O 只在乎 n 很大時的行為，所以結果是 O(n²)。課堂的練習題 `n² + 100000n + 3¹⁰⁰⁰` 也是同樣的道理：3¹⁰⁰⁰ 再大也是固定的數字，不會隨 n 成長。

#### 第 4 題：只有一個 for 迴圈

**題目：** 一個函式裡面只有一個 for 迴圈，所以它一定是 O(n)。

**答案：錯。**

複雜度要看迴圈跑幾次、以及每一次做了多少事，不能只數 for 的數量。課堂的 `intersect` 和 `is_subset` 提醒了這件事：`for e in L1: if e in L2:` 看起來只有一個迴圈，但對 list 使用 `in` 時，Python 會在背後逐一比對 L2 的每個元素，最壞要比 n 次，所以外層 n 次乘上每次 n 次，整體是 O(n²)（乘法規則）。反過來，如果迴圈固定只跑 10 次（例如 `for i in range(10)`），跟 n 無關，那就是 O(1)。

#### 第 5 題：在排好序的 list 裡線性搜尋

**題目：** 在排好序的 list 裡找一個數字，如果一邊找、一邊在「遇到比目標大的數字」時提早停下來，最壞情況的複雜度就會從 O(n) 降到比較小的等級。

**答案：錯。**

課堂比較了未排序與已排序 list 的線性搜尋。排好序之後，遇到比目標大的元素就可以提早回傳 False，平均情況確實比較快；但最壞情況是目標比 list 裡所有數字都大（或剛好是最後一個），還是得把 n 個元素全部看完，所以仍然是 O(n)。Big O 描述的是最壞情況，提早停下來只改善了常數或平均表現，沒有改變成長的等級。要真正利用「排好序」降低等級，需要每次把搜尋範圍砍半的二分搜尋，那是 Lecture 11 的內容。

### ② My Misconception

- **Before（常見誤解）：** 以為 O(1) 就是「只做一步」；也以為判斷複雜度只要數有幾個 for 迴圈，一個迴圈就是 O(n)、兩層才是 O(n²)。
- **Now（觀念整理）：** O(1) 是「步數固定、跟 n 無關」；判斷複雜度要看每一行實際做了多少事，list 的 `in`、`sum()`、`sort()` 這類函式背後也在跑迴圈，前後接著執行的程式碼用加法規則（留最大項），一段包在另一段裡面用乘法規則。

### ③ Challenge the AI

- **Question examined：** 第 4 題，一個 for 迴圈一定是 O(n)。
- **Why：** Ambiguous。
- **Brief explanation：** 題目只說「一個 for 迴圈」，沒有說迴圈跑幾次、裡面做了什麼。如果迴圈是 `for x in L`，答案取決於迴圈內容（例如有沒有用 list 的 `in`）；如果是 `for i in range(10)`，跑的次數固定，反而是 O(1)。同一句敘述在不同情況下會有 O(1)、O(n)、O(n²) 三種答案，所以標準答案雖然是「錯」，但題目沒有給出足夠資訊讓人判斷是哪一種錯法。改成附上一段具體程式碼，例如 `for e in L1: if e in L2: ...`，才能測出是否真的理解「藏起來的迴圈」。
