### 題目與解答

#### 第 1 題：遞迴的終止條件

**題目：** 一個函式只要會呼叫自己，就構成正確的遞迴，Python 會自動判斷何時停止。

**答案：錯。**

正確的遞迴需要兩個條件：至少一個不再呼叫自己的 base case，以及每次遞迴呼叫都要讓問題規模變小、朝 base case 收斂。缺少其中任何一個，呼叫就會一直疊下去，直到超過呼叫堆疊上限並丟出 RecursionError。語言本身不會替你判斷終止時機。

#### 第 2 題：遞迴與迭代的效率

**題目：** 遞迴寫法一定比用迴圈的迭代寫法更有效率。

**答案：錯。**

遞迴的優點是貼近問題的數學定義、程式碼通常較簡潔易讀，但每次呼叫都要配置新的堆疊框架，額外付出時間與記憶體成本。像費氏數列的樸素遞迴會重複計算同樣的子問題，複雜度是指數級，明顯比迴圈版本差。可讀性與效率是兩件事，要分開評估。

#### 第 3 題：字典的鍵

**題目：** Python 字典的鍵（key）必須是可雜湊（hashable）的物件，因此 list 不能當作鍵，但 tuple 可以。

**答案：對（但有但書）。**

字典用雜湊值定位資料，鍵必須可雜湊。list 是可變物件、不可雜湊，不能當鍵；tuple 通常可以。但書是：tuple 只有在它所有元素都可雜湊時才可雜湊，例如 `(1, [2])` 這種內含 list 的 tuple 一樣不能當鍵。

#### 第 4 題：字典的順序

**題目：** 字典是無序的集合，因此走訪字典時，元素出現的順序無法預期。

**答案：視 Python 版本而定。**

這是課程教材與現行語言行為有落差的地方。在舊版 Python 中字典確實不保證順序；但從 CPython 3.7 起，字典保留插入順序已經寫進語言規格，走訪時會依照插入先後。不過即使順序穩定，字典的用途仍是鍵值查找而不是序列操作，需要排序時應明確使用 `sorted()`。

#### 第 5 題：記憶法（memoization）

**題目：** 用字典把已經算過的結果記錄下來，可以把費氏數列的遞迴從指數時間降到線性時間。

**答案：對。**

樸素遞迴會重複求解同一個子問題，呼叫樹大量重疊。用字典當查找表，每個 n 只真正計算一次，之後直接取用，呼叫次數從指數級降到與 n 成正比。這個以空間換時間的技巧就是 memoization，前提是同樣的輸入一定得到同樣的輸出。

### ② My Misconception

- **Before（常見誤解）：** 以為遞迴只要寫出「自己呼叫自己」就會自動停止，也以為遞迴因為寫起來比較短，所以執行起來也比較快。
- **Now（觀念整理）：** 終止必須靠明確的 base case 加上規模遞減，兩者缺一不可；簡潔與效率是兩個獨立的面向，樸素遞迴甚至可能因為重複計算而遠慢於迴圈，要靠 memoization 才補得回來。

### ③ Challenge the AI

- **Question examined：** 第 4 題，字典是否無序。
- **Why：** Technically questionable。
- **Brief explanation：** 題目把「字典無序」當成絕對事實，但這是 Python 3.7 之前的行為。現行版本的字典保證保留插入順序，所以這個敘述在今天的 Python 已經不正確。題目應該標明討論的版本，或改問「是否應該依賴字典的順序來設計程式」，這樣才問得出真正該掌握的觀念。
