#### Question 1 — Independent instance data

- Statement: 在 `__init__` 中寫 `self.values = []`，通常會讓每個新建 instance 擁有自己的 list。
- Initial answer and reasoning: **對。** `self.values = []` 寫在 `__init__` 中，每次建立 instance 都會執行一次，產生一個新的 list 並綁定到該 instance。因此各物件的 list 彼此獨立。若改成寫在 class 層級（`values = []`），所有 instance 才會共用同一個 list。
- AI hint before answer: 無。
- Revised answer: 未修正。
- AI clarification after answer: class 層級的 list 由仍透過類別屬性取得它的 instances 共用；若某 instance 另外指派自己的 `self.values`，就會遮蔽同名類別屬性。
- Concept confirmed: instance attribute 與 class attribute 的差別；每次執行 list literal 都建立新 list。

#### Question 2 — Bound methods and self

- Statement: 呼叫 `obj.add(3)` 時，定義為 `def add(self, value)` 的 instance method 會接收到 `obj` 作為 `self`。
- Initial answer and reasoning: **對。** `obj.add(3)` 是 bound method 呼叫，Python 會自動把 `obj` 當作第一個參數傳入，即 `self`。`3` 則對應 `value`。這等同於 `Class.add(obj, 3)`。
- AI hint before answer: 無。
- Revised answer: 未修正。
- Concept confirmed: 對題目所示一般 instance method，bound method 將 instance 作為第一個引數；此處 Class 指定義相應 method 的類別。

#### Question 3 — Underscore naming convention

- Statement: 只要屬性名稱以單一底線開頭，例如 `obj._values`，Python 就會完全禁止外部程式讀取該屬性。
- Initial answer and reasoning: **錯。** 單一底線只是命名慣例，表示「內部使用、不建議外部存取」。Python 不會禁止讀取，`obj._values` 仍然可以正常存取。真正有機制作用的是雙底線（`__values`），它會觸發 name mangling，但那也不算完全禁止存取。
- AI hint before answer: 無。
- Revised answer: 未修正。
- Concept confirmed: 單一底線是慣例；類別中雙底線開頭且非雙底線結尾的名稱會發生 name mangling，並非安全存取控制。

#### Question 4 — String representation

- AI hint before answer: 無。
- Revised answer: 未修正。
- Concept confirmed: 在類別定義 `__str__` 以提供物件字串表示；回傳值必須為 str。

#### Question 5 — Aliasing and defensive copies

- Statement: 使用 `self.values = supplied_list`，就保證物件內部資料與呼叫者的 list 相互獨立。
- Initial answer and reasoning: **錯。** `self.values = supplied_list` 只是讓 `self.values` 和呼叫者的變數指向同一個 list 物件，並沒有複製。外部修改該 list（例如 `supplied_list.append(1)`），物件內部資料也會跟著改變，反之亦然。若要獨立，需用 `list(supplied_list)`、`supplied_list.copy()` 或 `supplied_list[:]` 複製。如果元素本身是可變物件，還需要 `copy.deepcopy`。
- AI hint before answer: 無。
- Revised answer: 未修正。
- AI clarification after answer: 只有需要連內層可變資料都互不影響時，才需要 deepcopy 或自行逐層建立獨立物件。本次 ReadingLog 的元素是不可變整數，淺拷貝即可滿足獨立性要求。
- Concept confirmed: 指派不等於複製；依實際資料結構及獨立性需求選擇複製深度。

### 1. Today's Challenge

**Title: Independent Reading Logs**

設計 `ReadingLog(initial_pages)`。建構時儲存已閱讀頁數的 list，並提供 `add(pages)`、`total()`、`snapshot()`。`add` 只接受非負整數，非法數值拋出 `ValueError`；`total` 回傳累計頁數；`snapshot` 回傳目前紀錄的複製 list。

Constraints:
- 建構子的初始 list 皆為非負整數，最多 100 個元素。
- 建構後，外部修改初始 list 不得改變物件紀錄。
- 外部修改 `snapshot()` 的結果不得改變物件紀錄。
- 每個 `ReadingLog` 物件的資料互相獨立。

Examples:
1. 以 `[5, 8]` 建構後 `add(3)`，`total()` → `16`，`snapshot()` → `[5, 8, 3]`
2. 以 `[]` 建構，`total()` → `0`
3. `add(-1)` → `ValueError`，原紀錄不變

Additional verification: 兩個物件、初始 list 和 snapshot 分別被修改後的影響。

```python
class ReadingLog:
    def __init__(self, initial_pages):
        self._pages = list(initial_pages)

    def add(self, pages):
        if type(pages) is not int or pages < 0:
            raise ValueError("pages must be a non-negative integer")
        self._pages.append(pages)

    def total(self):
        return sum(self._pages)

    def snapshot(self):
        return list(self._pages)
```
