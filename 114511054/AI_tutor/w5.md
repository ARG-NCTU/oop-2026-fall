#### Question 1 — Parent initialization

- Statement: 子類別定義自己的 `__init__` 後，Python 必定自動先呼叫父類別的 `__init__`。
- Initial answer and reasoning: **錯。** 子類別一旦定義自己的 `__init__`，就會覆蓋父類別的版本，Python 不會自動呼叫父類別的 `__init__`。要用 `super().__init__(...)` 明確呼叫，否則父類別在 `__init__` 裡設定的屬性不會出現。只有子類別完全沒定義 `__init__` 時，才會直接繼承並使用父類別的。
- AI hint before answer: 無。
- Revised answer: 未修正。
- Concept confirmed: 子類別覆寫初始化後，父類別初始化不會自動執行；super 可用來沿 MRO 呼叫下一個初始化方法。
- AI scope clarification: 初答描述本題一般單一繼承情況；super 不是唯一能明確呼叫既有初始化程式的方法，而父類別的初始化也不會替未執行的初始化內容建立屬性。

#### Question 2 — Overriding scope

- Statement: 子類別 override 某個 method 後，父類別自己的 instance 也會改成使用子類別的版本。
- Initial answer and reasoning: **錯。** override 只影響子類別（及其子孫）的 instance。直接建立的父類別 instance 仍使用父類別自己的 method，父類別本身不會被改動。
- AI hint before answer: 無。
- Revised answer: 未修正。
- Concept confirmed: 子類別定義新版本不會改寫父類別本身的方法。

#### Question 3 — Inherited methods

- Statement: 子類別沒有重新定義的 method，仍可能從父類別繼承並使用。
- Initial answer and reasoning: **對。** 子類別沒有重新定義的 method，會沿著 MRO（方法解析順序）往父類別找，找到就能直接使用。
- AI hint before answer: 無。
- Revised answer: 未修正。
- Concept confirmed: 一般方法查找遵循 MRO；不同類別內的雙底線名稱會受到 name mangling 影響，詳見挑戰題。

#### Question 4 — Attribute shadowing

- Statement: 當 `Base.count` 是整數時，對 instance 執行 `obj.count = 9`，必定會把 `Base.count` 改為 9。
- Initial answer and reasoning: **錯。** `obj.count = 9` 會在 `obj` 自己的 `__dict__` 建立一個同名的 instance 屬性，遮蔽（shadow）類別屬性。`Base.count` 不變，其他 instance 讀到的仍是原值。要改類別屬性，必須寫 `Base.count = 9`。
- AI hint before answer: 無。
- Revised answer: 未修正。
- AI scope clarification: 這是一般具有 instance __dict__、沒有自訂屬性指派機制的類別之行為；修改類別屬性可用 Base.count 指派，並非只有這一種語法能修改類別屬性。
- Concept confirmed: instance 屬性與 class 屬性是不同的儲存位置，前者可以遮蔽後者。

#### Question 5 — Polymorphism

- Statement: 對不同子類別物件呼叫相同 method 名稱，可以產生不同結果，而呼叫端不一定要先判斷它們的具體類別。
- Initial answer and reasoning: **對。** 這就是多型（polymorphism）。呼叫端只依賴 method 名稱與介面（duck typing），實際執行哪個版本由物件的真實型別決定，所以不必用 `isinstance` 先判斷。
- AI hint before answer: 無。
- Revised answer: 未修正。
- Concept confirmed: 以共同介面操作物件，可讓實際方法實作決定行為；duck typing 也可以用於沒有共同父類別但提供相容介面的物件。

### 1. Today's Challenge

**Title: Delivery Fee Polymorphism**

設計 `Delivery(weight)` 及兩個子類別 `StandardDelivery`、`ExpressDelivery`。父類別保管整數重量，負重量拋出 `ValueError`。共同方法 `fee()` 依物件種類回傳費用：Standard 為 `40 + 8 * weight`；Express 為 `90 + 15 * weight`。父類別的 `fee()` 回傳 0。

另實作 `total_fee(deliveries)`，加總 list 中各物件的費用。

Constraints:
- 重量為 0–100 的整數；傳入負值需被拒絕。
- 子類別共用父類別的重量初始化與檢查，避免重複實作。
- 加總函式以共同介面呼叫，不用具體類別分支決定計費方式。
- 最多 100 筆 delivery。

Examples:
1. 一筆 Standard，重量 2 → `56`
2. 一筆 Express，重量 2 → `120`
3. 兩筆以上述物件組成的 list → `total_fee` 為 `176`；空 list → `0`

Additional verification: 0 重量、負重量，以及混合父類別與子類別的 list。

```python
class Delivery:
    def __init__(self, weight):
        if weight < 0:
            raise ValueError("weight must be non-negative")
        self.weight = weight

    def fee(self):
        return 0


class StandardDelivery(Delivery):
    def fee(self):
        return 40 + 8 * self.weight


class ExpressDelivery(Delivery):
    def fee(self):
        return 90 + 15 * self.weight


def total_fee(deliveries):
    total = 0
    for d in deliveries:
        total += d.fee()
    return total
```
