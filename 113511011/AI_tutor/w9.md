### ① Check My Understanding

**Question 1 — Objective versus constraint** (pp. 9, 13–14)  
**True or False:** In a model maximizing learning value under a time budget, total learning value is the objective and total time ≤ budget is a constraint.

**My answer:** True. A feasible plan respects the time limit; its quality is measured separately by the objective.  
**AI follow-up:** Does feasibility alone establish optimality?  
**My explanation:** No. Many feasible subsets can have different total values. An optimum must have at least as much value as every other feasible subset in the model.

**Question 2 — Density and indivisible items** (pp. 11, 18, 29–30)  
**True or False:** Selecting whole items by decreasing value/cost always finds an optimal 0/1 knapsack solution.

**My first answer:** True; each unit of capacity buys the greatest value.  
**AI Tutor hint:** Budget 50; items `(value, cost)` are `(60, 10)`, `(100, 20)`, `(120, 30)`. Which items does density take, and what other pair fits?  
**My revised answer:** False. Density takes the first two, value 160 and cost 30; the last no longer fits. The second and third together cost 50 and yield 220.  
**Explanation:** In 0/1 knapsack I cannot take part of the remaining item. The standard density guarantee for fractional knapsack assumes divisible items, positive costs and proportional value, so it does not transfer to indivisible choices.

**Question 3 — Enumerating subsets** (pp. 15–16)  
**True or False:** n distinct available items have 2ⁿ subsets, including the empty subset; independently summing every subset by scanning all n items takes O(n·2ⁿ) time.

**My answer:** True. Each item has two inclusion decisions, and the naïve evaluator checks n decisions for each combination.  
**AI follow-up:** Must we retain all subsets simultaneously?  
**My explanation:** No. We can evaluate one subset at a time and retain the best. Exponential search time does not imply exponential peak memory for every implementation.

**Question 4 — A rejected item** (greedy loop, p. 23)  
**True or False:** While scanning items by priority, if the next item does not fit the remaining budget, the greedy algorithm can stop because every later item also fails to fit.

**My first answer:** True; the best candidate has already been examined.  
**AI Tutor hint:** A value-first ordering encounters `(100, 9)` then `(4, 2)` under budget 2. Does value order imply cost order?  
**My revised answer:** False. Skip the first item and continue; the second fits exactly.  
**Explanation:** Priority and affordability are different properties. The lecture's loop checks every item, using `<=` for feasibility, and does not `break` when one item fails.

**Question 5 — Sorting cost** (pp. 23–24, 27)  
**True or False:** With a constant-time key, sorting n items once and then making a single greedy pass has O(n log n) worst-case time, even though the pass itself is linear.

**My answer:** True. Sorting dominates the O(n) scan.  
**AI follow-up:** Does passing a different function as the sorting key change the whole algorithm?  
**My explanation:** It changes the priority rule while reusing the same feasibility loop. Constant-time keys preserve the bound; an expensive key would need its own cost analysis. Sorting a copied list also preserves the caller's item order.

### ② My Misconception

**Before:** I equated a locally attractive density with global optimality, and confused an item's high priority with its affordability.  
**Now:** A greedy policy commits without exploring alternatives. It maintains feasibility, but does not establish optimality for 0/1 choices. Rejected items must not prevent consideration of cheaper later items. Counterexamples expose both errors more clearly than testing only easy cases.

### ③ Challenge the AI

**Statement challenged:** “0/1 knapsack is inherently exponential.” (p. 17)

- [x] Oversimplified
- [x] Technically questionable without a complexity assumption
- [ ] Too easy

**Why:** The lecture motivates why enumerating 2ⁿ subsets is impractical. That does not prove every possible exact algorithm must have exponential runtime. The general problem is NP-hard; no polynomial-time exact algorithm is known. Integer-capacity dynamic programming can be pseudo-polynomial, which is an extension beyond this lecture, not an algorithm used in this submission.

**Better question:** “Does the lecture's exhaustive subset enumeration require exponentially many candidates in n?” True. This states what the demonstrated algorithm actually does without claiming an unconditional lower bound for all algorithms.

### 1. Today's Challenge

**Problem:** A club has a time budget and a list of optional workshops `(learning_value, duration)`. Every workshop is indivisible and may be chosen at most once. There are no scheduling conflicts or prerequisites in this model. Generate three feasible plans using these priority orders:

1. `value`: decreasing learning value.
2. `cost`: increasing duration.
3. `density`: decreasing learning value / duration.

Equal priorities retain original input order. Scan every workshop in that order; accept it exactly when it fits the remaining budget. Select the plan with greatest total learning value; equal totals prefer policies in the order `value`, `cost`, `density`. Return `(chosen_indices, total_value, used_time, policy_name)`, with indices in acceptance order.

Density uses bounded numeric inputs; zero duration is excluded.

**Required guarantee:** Correctly implement the three policies and choose their best result. ### 4. My Revision

Wrap each original `(value, duration)` with its index in a `Workshop` object. One generic `greedy_plan` function sorts a copy using a supplied key. I use `value`, negative duration and density as descending keys. For each policy I start fresh totals, scan all records, and append only affordable indices. The controller evaluates the three policies in the specified order and retains the first maximum.

**Audit counterexample:** Budget 10, workshops `[(17, 9), (10, 3), (14, 3), (7, 5), (16, 5)]`. Value-first yields 17; cost-first yields 24; density-first yields 24. The controller returns `([1, 2], 24, 6, 'cost')`. Choosing workshops 2 and 4 instead yields 30 in 8 time units. An exact subset oracle will verify that 30 is the optimum. Thus “best of three” still does not mean globally optimal.

### Python Program

```python
"""Lecture 1 transfer: compare three feasible workshop-selection policies."""


class Workshop:
    def __init__(self, index, value, duration):
        self.index = index
        self.value = value
        self.duration = duration

    def density(self):
        return self.value / self.duration


def greedy_plan(items, budget, key_function):
    """Return accepted indices, total value and used time; keep inputs intact."""
    ordered = sorted(items, key=key_function, reverse=True)
    chosen = []
    total_value = used_time = 0
    for item in ordered:
        if used_time + item.duration <= budget:
            chosen.append(item.index)
            total_value += item.value
            used_time += item.duration
    return chosen, total_value, used_time


def plan_workshops(workshops, budget):
    """Choose the first maximum-value plan among value, cost and density.

    Preconditions: nonnegative integer values and budget; positive durations.
    This is a best-of-three heuristic, not an exact knapsack solver.
    """
    items = [Workshop(i, value, duration)
             for i, (value, duration) in enumerate(workshops)]
    policies = [
        ("value", lambda item: item.value),
        ("cost", lambda item: -item.duration),
        ("density", lambda item: item.density()),
    ]
    best = None
    for name, key in policies:
        chosen, value, used = greedy_plan(items, budget, key)
        if best is None or value > best[1]:
            best = (chosen, value, used, name)
    return best
```

**Why the solution works for its contract:** Each policy sorts every original index exactly once, with stable ties. Before and after every scan step, the accumulated time and value equal the sums of the accepted workshops, indices are distinct, and used time is at most the budget. Accepting an item only after `used + cost <= budget` preserves the invariant; rejecting it leaves the invariant intact and scanning continues. Thus the result is precisely the plan defined by that policy. The controller's invariant is that `best` is the first maximum-value policy among those already considered. Strict `>` preserves the specified tie preference. After three iterations it returns the required winner. This proves policy execution, not global knapsack optimality.

**Time complexity:** For n ≥ 2, each constant-key sort costs O(n log n) worst-case and its scan costs O(n). Three policies are a constant factor: O(3n log n + 3n) = O(n log n). Empty/singleton inputs take O(1). Values and durations have bounded sizes; score-key evaluation is treated as constant time.

**Space complexity:** O(n) auxiliary space for wrapped records, sorted copies and selected index lists. At most a constant number of policy results coexist; holding three candidates would still be O(n). Sorting can use O(n) temporary storage. Returned selected indices occupy O(n). No recursive search or exponential oracle is part of `plan_workshops`.

**Oracle cost, separate from the solution:** The test-only optimum evaluator scans n decisions for each of 2ⁿ masks: O(n·2ⁿ) time and O(1) counters aside from the input under a fixed-word model for these tiny tests. It never materializes the entire power set. It is deliberately limited to small instances; its cost is not included in the planner's complexity. Enumerating test families also takes additional time proportional to the number of test instances.

**Numerical note:** Density keys use Python division as in the lecture. Under the bounded integer constraints, unequal positive ratios differ by at least 1/10000², comfortably larger than floating-point rounding errors at these magnitudes. Equal rational ratios round consistently, and stable sorting handles their ties. Tests use `Fraction` keys as an independent exact check. Unbounded integers would require a different numerical analysis.
