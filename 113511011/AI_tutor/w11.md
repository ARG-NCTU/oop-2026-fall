### ① Check My Understanding

**Question 1 — What information does an edge carry?** (pp. 4–6, 11, 21)  
**True or False:** Direction and weight are separate modeling choices: a directed graph can be unweighted, and an undirected graph can be weighted.

**Practice answer:** True. A node, also called a vertex, represents an entity; an edge links two entities. A directed edge `A -> B` permits travel from A to B without promising a return edge. An undirected edge permits both directions. A weight can represent travel time, distance or another cost.  
**AI follow-up:** Is a route with two roads necessarily faster than one with three roads?  
**Explanation:** No. In an unweighted model every edge contributes one hop; in a weighted model the objective may be the sum of edge costs. Choosing nodes, directions and weights is part of defining the problem, before selecting a search algorithm. An isolated vertex is still part of the graph even if it appears in no edge.

**Question 2 — Is every graph a tree?** (p. 7)  
**True or False:** A connected graph is necessarily a tree, so cycle checks are unnecessary when searching it.

**Initial practice answer:** True; connected means every node can be reached.  
**AI Tutor hint:** Draw the undirected triangle A—B—C—A. Is it connected? Is there only one simple path from A to C?  
**Revised answer:** False. The triangle is connected and has a cycle. An undirected tree is connected and acyclic; exactly one simple path joins each pair of vertices. A general graph may have cycles, multiple paths or disconnected components.  
**Explanation:** The lecture uses rooted search trees as a directed special case. Orienting tree edges away from the root gives one directed root-to-node path, not a directed path between every ordered pair. Sibling nodes need not reach each other. This clarifies the scope of the slide's “single path” description.

**Question 3 — Representation and inheritance** (pp. 15–20)  
**True or False:** An undirected `Graph` can reuse a `Digraph` adjacency-list implementation by storing both directions of each edge and overriding edge insertion.

**Practice answer:** True. If A connects to B, store B among A's children and A among B's children. Both classes can provide `addNode`, `addEdge`, `childrenOf` and `hasNode`.  
**AI follow-up:** Why not have the override call `self.addEdge()` to insert the reverse direction?  
**Explanation:** That would call the override again and recurse indefinitely. Call the superclass method for each directed insertion. A search using the shared neighbor interface can work on either class; a function assuming symmetric neighbors cannot safely accept an arbitrary digraph. Inheritance should preserve the documented interface and behavior, not merely reduce typing.

**Question 4 — The first DFS answer** (pp. 25–31)  
**True or False:** DFS's first discovered route is always a shortest route in an unweighted graph.

**Initial practice answer:** True; it reaches the destination without wasting time on other branches.  
**AI Tutor hint:** Insert edges in this order: `S->A`, `A->B`, `B->T`, `S->T`. Which route does first-child DFS find first?  
**Revised answer:** False. It can find `S,A,B,T` before the one-edge route `S,T`. Shortest-path DFS must continue exploring alternatives, track the best complete path and prune only when justified.  
**Explanation:** A current-path membership check avoids cycles while allowing a node to be revisited through a different candidate route. A global visited set is useful for ordinary reachability DFS, but marking a node forever after a long route can hide a shorter arrival when implementing this exhaustive shortest-path variant.

**Question 5 — What BFS guarantees** (pp. 32–36)  
**True or False:** FIFO breadth-first search finds a minimum-hop route in an unweighted graph, but does not generally minimize arbitrary edge weights.

**Practice answer:** True. FIFO expansion reaches all distance-k vertices before distance-(k+1) vertices. With `S->T` of weight 10 and `S->A->T` with weights 1 and 1, BFS prefers one hop even though its cost is larger.  
**AI follow-up:** Can a node be marked discovered when it is enqueued?  
**Explanation:** Yes, for this unweighted minimum-hop contract. Its first discovery already has minimum distance, so another equal or longer arrival need not be enqueued. Store a predecessor to reconstruct the route. This is an intentional improvement over the lecture's queue of entire paths, which only rejects vertices already in each current path and may queue a vertex through multiple routes.

### ② My Misconception — Practice Revision

**Before:** Finding any route seemed equivalent to finding the shortest one, and the word “visited” seemed to mean one universal rule.  
**Now:** DFS's path-local exclusion and BFS's discovery set serve different proofs. A route's objective must also be explicit: the fewest edges and the smallest sum of weights need not agree.

### ③ Challenge the AI

**Statement challenged:** “BFS always takes O(V+E) time and space.”

- [x] Oversimplified
- [x] Technically questionable without implementation details
- [ ] Too easy

**Why:** The usual time bound assumes adjacency lists, one discovery per vertex and efficient queue operations. The lecture's path queue copies paths and uses `pop(0)`, which shifts a Python list. It can keep many paths ending at the same vertex. The algorithm name alone does not prove that implementation has the textbook bound. For the implementation below, the search uses O(V+E) time and O(V) extra space; the stored graph itself uses O(V+E) space.

**Better question:** “With each vertex enqueued once, a queue head index, and one predecessor per vertex, is unweighted BFS linear in the adjacency-list graph size?” Yes, assuming expected constant-time dictionary/set operations.

### ④ One-Minute Reflection — Practice Prompt

**Suggested corrected misconception:** A graph model is not automatically a tree, and a DFS call tree is not the same object as the graph being searched.  
**Remaining question:** How do adjacency order and equal-length alternatives affect the route returned? Define deterministic behavior before treating a different valid shortest route as a test failure.

### 1. Today's Challenge

**Problem:** Find a minimum-hop route between two campus locations while avoiding a supplied collection of closed locations. Model locations as `Node` objects and walkways as `Edge` objects. A `Digraph` models one-way walkways; `Graph` models two-way walkways using the same adjacency-list interface. Implement both shortest-path DFS and BFS. Neither query may remove nodes or edges from the stored graph.

**Input / Output:** `DFS(graph, start, end, closed=(), trace=None)` and `BFS(graph, start, end, closed=(), trace=None)` each return a list of the original `Node` objects including both endpoints, or `None` if no allowed route exists. `route_names(path)` converts a result to a list of names for display, retaining `None` for failure. A closed start or destination gives `None`; an open start equal to the destination gives `[start]`. An endpoint absent from the graph raises `ValueError`.

**Constraints:** 1 ≤ V ≤ 8 for combined DFS/BFS tests; no duplicate ordered edges or self-loops in challenge inputs; unique location names; all edge endpoints and closed locations belong to the graph. Every edge has unit cost. Follow adjacency insertion order. If several shortest routes exist, either is acceptable, but each algorithm must be deterministic for a fixed input; DFS retains the first shortest candidate it discovers and BFS retains first-discovery predecessors. Use a larger sparse case only for BFS. These small DFS constraints reflect its potential combinatorial search cost.

**Shared example graph:** Nodes `S,A,B,T,X`. Directed edges in insertion order are `S->A`, `A->B`, `B->T`, `S->T`, `B->S`. X is isolated. The first DFS route to T follows three edges, but the exact result must use the later direct edge.

### 2. My Initial Approach — Practice Proposal

**Proposed approach:** Delete closed vertices from the graph, run recursive DFS, and return the first route reaching the goal. Reuse one visited set across all recursive branches.  
**Concept to transfer:** Represent neighbor relationships in an adjacency list and follow them recursively, similarly to the knapsack search tree.

**AI Tutor:** “After a query with A closed, what would a second query with no closures see? Which path does DFS find first in the example?”  
**Practice response:** Deleting A would corrupt later queries, and first-route DFS would return three edges instead of one. Closures should filter neighbor expansion, and DFS should compare complete routes instead of immediately stopping the whole search.

**AI Tutor:** “Try `S->A->B->X->T` before `S->X->T`. Can a permanent visited mark on X hide the shorter route?”  
**Practice response:** Yes. Use only the current recursion path to reject repeated vertices in shortest-path DFS. Backtracking must permit X on another candidate path. BFS can instead mark X globally at enqueue time because its first discovery is already at minimum hop count.

### 4. My Revision — Representation and Search

`Node` holds a name; object identity distinguishes vertices. Keep and reuse the original instances when adding edges and making queries: constructing another `Node('S')` does not retrieve the existing S. `Edge` holds source and destination. `Digraph.edges` maps every node to an insertion-ordered list of outgoing neighbors, including an empty list for isolated nodes. `Graph.addEdge` calls the parent implementation twice, once per direction. Duplicate node objects and missing edge endpoints raise `ValueError`.

For DFS, copy the current path when descending. Update the best route only when a strictly shorter complete route is found. If a partial path already contains at least as many nodes as the best complete route, extending it cannot improve the answer. For BFS, keep a list queue and advance a head index rather than shifting it with `pop(0)`. Store each newly discovered vertex's predecessor, which also marks it visited. Reconstruct one route after the destination is dequeued. Both solvers create a set of closed nodes and skip them without editing the graph.

**Adjacency-list trace:** The example stores `S:[A,T]`, `A:[B]`, `B:[T,S]`, `T:[]`, `X:[]`. DFS descends through A and B, rejects B's edge back to S because S is already in the path, then considers the direct S-to-T alternative. BFS expands S, A and T, stopping at T before expanding B. Both are correct, but they do different amounts and orders of work.

### Python Program

```python
"""Lecture 3 transfer: shortest open routes on directed or undirected graphs."""


class Node:
    def __init__(self, name):
        self.name = name

    def getName(self):
        return self.name

    def __str__(self):
        return self.name


class Edge:
    def __init__(self, src, dest):
        self.src, self.dest = src, dest

    def getSource(self):
        return self.src

    def getDestination(self):
        return self.dest

    def __str__(self):
        return f'{self.src}->{self.dest}'


class Digraph:
    def __init__(self):
        self.edges = {}

    def addNode(self, node):
        if self.hasNode(node):
            raise ValueError('Duplicate node')
        self.edges[node] = []

    def addEdge(self, edge):
        src, dest = edge.getSource(), edge.getDestination()
        if not self.hasNode(src) or not self.hasNode(dest):
            raise ValueError('Endpoint not in graph')
        self.edges[src].append(dest)

    def hasNode(self, node):
        return node in self.edges

    def childrenOf(self, node):
        return self.edges[node]


class Graph(Digraph):
    def addEdge(self, edge):
        super().addEdge(edge)
        super().addEdge(Edge(edge.getDestination(), edge.getSource()))


def query_allowed(graph, start, end, closed):
    if not graph.hasNode(start) or not graph.hasNode(end):
        raise ValueError('Endpoint not in graph')
    return start not in closed and end not in closed


def DFS(graph, start, end, closed=(), trace=None):
    """Compare simple paths, pruning prefixes unable to improve the best."""
    closed = set(closed)
    if not query_allowed(graph, start, end, closed):
        return None
    best = None

    def visit(node, path):
        nonlocal best
        path = path + [node]
        if trace is not None:
            trace.append(tuple(str(n) for n in path))
        if node is end:
            if best is None or len(path) < len(best):
                best = path
            return
        if best is not None and len(path) >= len(best):
            return
        for child in graph.childrenOf(node):
            if child not in closed and child not in path:
                visit(child, path)

    visit(start, [])
    return best


def BFS(graph, start, end, closed=(), trace=None):
    """Discover each vertex once; reconstruct a minimum-hop open route."""
    closed = set(closed)
    if not query_allowed(graph, start, end, closed):
        return None
    queue, head = [start], 0
    parent = {start: None}
    while head < len(queue):
        node = queue[head]
        head += 1
        if trace is not None:
            trace.append(str(node))
        if node is end:
            path = []
            while node is not None:
                path.append(node)
                node = parent[node]
            return path[::-1]
        for child in graph.childrenOf(node):
            if child not in closed and child not in parent:
                parent[child] = node
                queue.append(child)
    return None


def route_names(path):
    return None if path is None else [str(node) for node in path]
```

**Trace interpretation:** DFS records every entered candidate path, including complete routes. BFS records dequeued vertices, including the destination. The five DFS entries and three BFS entries measure these specific events, not an equal-cost instruction count or a universal speed ratio. The edge B-to-S is rejected in DFS because S is in the current path. In BFS, S is already discovered. Both protections prevent cycles, but BFS additionally avoids duplicate arrivals from separate paths.

**Why DFS works:** All considered paths use existing edges and avoid closed vertices. Rejecting a vertex already on the current path is safe: a minimum-hop route has no cycle, since deleting a cycle shortens it. Every remaining simple route is explored unless its prefix is already too long to improve the best complete route. Because extending a prefix increases its length, that pruning cannot discard a strictly better solution. The best variable therefore ends with minimum length, or stays `None` when no route exists. Strict improvement keeps the first equal-length winner. Each recursive path has at most V vertices, guaranteeing termination under the small-input contract.

**Why BFS works:** Initially the queue contains the start at distance zero. Expanding a distance-k vertex appends undiscovered neighbors at distance k+1 after earlier queued vertices. Thus dequeue distances never decrease, and the first predecessor assigned to a vertex realizes a minimum-hop route. When the destination is dequeued, following predecessors reaches the start with no repeated vertices. Skipping closed nodes simply searches the induced open-node graph. A disconnected destination is never discovered, and an exhausted queue correctly returns `None`.

**Time and space:** Adjacency lists occupy O(V+E) space; an undirected edge occupies two entries. For BFS, every vertex enters the queue at most once and each outgoing adjacency list is scanned at most once, giving O(V+E) time and O(V) auxiliary space, including closures, queue, predecessors and reconstruction. The head-index queue retains consumed entries but still contains at most V entries. These bounds use expected constant-time hashing and bounded-cost node names.

For shortest-path DFS, the O(V+E) bound for a single reachability traversal does not apply: one vertex may be revisited along many simple paths. Let P be the number of recursive path prefixes actually entered. Path copying costs O(V); scanning up to V neighbors with list-based membership checks gives a conservative O(PV²) time bound for these simple graphs. P can grow on the order of V! in dense cases with an unreachable destination, so pruning is not a polynomial-time guarantee. Without tracing, simultaneously live copied paths can occupy O(V²) auxiliary space. Optional DFS trace storage adds O(PV); BFS trace storage adds O(V). Tests keep exhaustive graphs tiny and use the 2000-node chain only for iterative BFS, avoiding a misleading large recursive demonstration.

### 6. One-Minute Reflection — Practice Prompt

**Lecture idea transferred:** Nodes and neighbor lists separate graph representation from query logic. Inheritance changes how edges are inserted while preserving the interface both searches need.  
**Suggested takeaway:** BFS's first-discovery rule is supported by its distance order. DFS must preserve alternatives when it is used to optimize path length. Temporary closures are query state, so applying them must not destroy the original network.
