### AI Tutor Learning Record — Practice Q&A

### ① Check My Understanding

**Question 1 — Fast and optimal are different** (pp. 3–4)  
**True or False:** A density-based greedy algorithm is attractive because it is simple and fast, but a feasible result need not maximize value in 0/1 knapsack.

**Practice answer:** True. With `(value, cost)` items `[(6, 2), (10, 4), (12, 5)]` and budget 9, density chooses the first two for value 16. The last two fit together and give 22.  
**AI follow-up:** Why not fill the last three units with part of the third item?  
**Revised explanation:** 0/1 means take an entire item once or omit it. Fractional choices would change the problem. Greedy avoids exploring combinations, which is its practical advantage, but the chosen priority alone supplies no exactness proof. Brute force can certify the optimum by comparing every feasible subset, at a much higher cost.

**Question 2 — Tree depth versus work** (pp. 5–10)  
**True or False:** Since a take/skip recursion has depth n, `maxVal()` needs only O(n) calls.

**Initial practice answer:** True; each call removes one item.  
**AI Tutor hint:** When every item fits, how many decision prefixes exist at depths 0, 1, 2 and 3?  
**Revised answer:** False. There are 1, 2, 4 and 8. A complete decision tree has 2ⁿ leaves and 2ⁿ⁺¹−1 nodes. Linear depth bounds the call stack, not the total number of calls.  
**Explanation:** Skipping an infeasible take branch helps individual instances but does not remove the exponential worst case. The recursive implementation need not allocate a tree object: arguments represent states, and returning from calls performs backtracking.

**Question 3 — What belongs in a state?** (pp. 24–28)  
**True or False:** Remaining capacity alone is a sufficient memo key for all recursive knapsack calls.

**Initial practice answer:** True; capacity determines what fits.  
**AI Tutor hint:** Under capacity 2, compare a remaining suffix containing `(9, 2)` with an empty suffix.  
**Revised answer:** False. Their answers are 9 and 0. The state needs both the remaining items and capacity. With a fixed item order, `(next_index, remaining_capacity)` identifies the suffix without copying it.  
**Explanation:** The accumulated value of earlier decisions is not part of the suffix optimum. It is added by callers. The lecture's suffix-length key is sufficient only within a fixed original sequence; unrelated top-level inputs must not share that memo.

**Question 4 — Why dynamic programming helps** (pp. 18–27)  
**True or False:** Optimal substructure justifies solving smaller optimization problems; overlapping subproblems explain why saving their answers can reduce repeated computation.

**Practice answer:** True. For item i, compare skipping it with taking it plus an optimal suffix answer under the reduced capacity. If that suffix answer were not optimal, replacing it with a better one would improve the whole candidate.  
**AI follow-up:** Must the original items be duplicates for states to overlap?  
**Explanation:** No. Distinct items can have equal costs. With costs `[2, 2, 3]` and budget 4, taking only the first or only the second reaches the same suffix starting at index 2 with capacity 2. Different earlier values do not change that suffix problem. Memoization is top-down dynamic programming: look up the state before computing, then store its answer. It trades additional storage for fewer repeated evaluations.

**Question 5 — What does “fast” mean?** (pp. 28–30)  
**True or False:** `fastMaxVal()` is always linear in the number of items, regardless of capacities and costs.

**Practice answer:** False. For nonnegative integer capacity B, there are at most `(n+1)(B+1)` index/capacity pairs. A scalar-value implementation has O(nB) time and space bounds when B ≥ 1, with constant-time arithmetic and expected dictionary operations.  
**AI follow-up:** Is O(nB) polynomial in the binary input length?  
**Explanation:** Not generally: B needs only O(log B) bits to encode. This is a pseudo-polynomial bound. Sparse memoization visits only reachable states, but when subset sums are mostly distinct it can still encounter many states. Real-valued costs do not supply the same integer-capacity bound. Returning and copying chosen-item tuples introduces additional work beyond scalar transitions.

### ② My Misconception — Practice Revision

**Before:** A recursion that advances one item at a time seems linear, and caching by capacity seems enough.  
**Now:** The branching factor determines how much work repeats. A cache is correct only if its key identifies the entire remaining problem; a small but incomplete key can return a fast, wrong answer.

### ③ Challenge the AI

**Statement challenged:** “Adding a memo makes knapsack efficient on every input.”

- [x] Oversimplified
- [x] Technically questionable without assumptions
- [ ] Too easy

**Why:** A dictionary cannot merge genuinely different states. Small integer capacities provide a useful state bound, while large and diverse costs may produce little reuse. A benchmark showing fewer calls on one family is evidence about that family, not a universal runtime guarantee.

**Better question:** “For fixed positive integer costs and integer budget B, can memoization evaluate each reachable suffix/capacity state at most once?” Yes, with a correct key and a memo scoped to that input.

### ④ One-Minute Reflection — Practice Prompt

**Suggested corrected misconception:** Search depth, number of calls and number of distinct states are three separate quantities.  
**Remaining question to investigate:** How much memory is spent on cached chosen-item tuples compared with cached values alone? Count both before claiming O(nB) space for a particular Python implementation.
