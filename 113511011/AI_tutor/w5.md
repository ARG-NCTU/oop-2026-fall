```
Question 1:
True or False:
If Person inherits from Animal, then a Person object can use get_age() even if get_age() is only defined in Animal.

My answer:
True.

Reason:
When Python evaluates a method call on a Person object, it first looks for the method in Person.

If the method is not found there, Python continues searching up the inheritance hierarchy.

For example:

class Animal(object):
    def get_age(self):
        return self.age

class Person(Animal):
    pass

p = Person()

If p has an age attribute, then:

p.get_age()

can use Animal.get_age() because Person inherits from Animal.


Question 2:
True or False:
If Person defines its own __init__, Python will automatically run Animal.__init__ before running Person.__init__.

My first answer:
True.

AI hint:
Consider this code:

class Animal(object):
    def __init__(self, age):
        self.age = age
        self.name = None

class Person(Animal):
    def __init__(self, name, age):
        self.friends = []

If Python automatically runs Animal.__init__, where in Person.__init__ is age passed to Animal?

My revised answer:
False.

Reason:
If a subclass defines its own __init__, the parent __init__ is not automatically called.

The subclass must explicitly call it, for example:

Animal.__init__(self, age)

or, in modern Python:

super().__init__(age)

This is important because the parent class may initialize several attributes, not only age.


Question 3:
True or False:
If Person.__init__ uses self.age = age instead of Animal.__init__(self, age), then the inherited get_age() method can still work.

My answer:
True.

Reason:
Animal.get_age() is:

def get_age(self):
    return self.age

Therefore, as long as the Person instance has an attribute named age, the inherited method can read it.

For example:

class Person(Animal):
    def __init__(self, name, age):
        self.age = age
        self.set_name(name)
        self.friends = []

Then:

p = Person("Amy", 20)
p.get_age()

can still return 20.

However, this does not mean skipping Animal.__init__ is always a good design.

If Animal.__init__ also creates other attributes, such as:

self.name = None
self.alive = True
self.energy = 100

then manually writing only:

self.age = age

would skip the rest of the initialization.

Therefore, calling the parent initializer is usually safer and better for reuse.


Question 4:
True or False:
A class variable such as Rabbit.tag gives every Rabbit object its own independent copy of tag.

My first answer:
True.

AI hint:
Suppose:

class Rabbit(Animal):
    tag = 1

and every new Rabbit executes:

self.rid = Rabbit.tag
Rabbit.tag += 1

If every instance had its own separate tag, how could the value increase globally from one Rabbit creation to the next?

My revised answer:
False.

Reason:
Rabbit.tag is a class variable.

It belongs to the class and is shared by Rabbit instances.

For example:

r1 = Rabbit(1)
r2 = Rabbit(2)
r3 = Rabbit(3)

can produce:

r1.rid == 1
r2.rid == 2
r3.rid == 3

while Rabbit.tag continues increasing.

In contrast:

self.rid
self.parent1
self.parent2

are instance attributes and belong to each individual Rabbit object.


Question 5:
True or False:
If a subclass defines a method with the same name as a method in its superclass, the subclass version is used for instances of the subclass.

My answer:
True.

Reason:
This is method overriding.

For example:

class Person(Animal):
    def speak(self):
        print("hello")

class Student(Person):
    def speak(self):
        print("I have homework")

For:

s = Student(...)

calling:

s.speak()

uses Student.speak() because Python starts method lookup from the actual class of the object.

If Student did not define speak(), Python would continue searching in Person and then higher in the hierarchy.


② My Misconception

Before: I thought…

I thought that inheritance meant the parent constructor would automatically execute whenever a subclass object was created.

I also thought that inherited methods somehow depended on the parent constructor having been called.

For example, I was unsure whether this would work:

class Person(Animal):
    def __init__(self, name, age):
        self.age = age

p = Person("Amy", 20)
p.get_age()


Now: I understand…

Now I understand that inheritance of methods and initialization are related but different ideas.

Person inherits get_age() because get_age() is available through the class hierarchy.

If get_age() contains:

return self.age

then it only requires that the current object actually has an age attribute.

Therefore:

self.age = age

can make the inherited get_age() work.

However, calling:

Animal.__init__(self, age)

does something more important than merely creating self.age.

It reuses all initialization logic defined by Animal.

If Animal later adds more attributes, Person automatically receives that initialization as long as it calls the parent constructor.

Therefore the better design is generally:

class Person(Animal):
    def __init__(self, name, age):
        Animal.__init__(self, age)
        self.set_name(name)
        self.friends = []

or:

class Person(Animal):
    def __init__(self, name, age):
        super().__init__(age)
        self.set_name(name)
        self.friends = []

Brief explanation:

The statement mixes together two separate mechanisms:

1. method inheritance
2. instance initialization

A subclass can inherit a method even if the superclass __init__ was not called.

Whether that inherited method works depends on what attributes it needs.

For example:

class Animal(object):
    def get_age(self):
        return self.age

class Person(Animal):
    def __init__(self, age):
        self.age = age

p = Person(20)

p.get_age()

still works because p has self.age.

However, if an inherited method needs an attribute that only Animal.__init__ normally creates and Person does not create it manually, then the method may fail with AttributeError.

So the better statement is:

"Skipping the superclass __init__ does not remove inherited methods, but it may leave the object missing state that inherited methods expect."
```

## Final Program

```python
class Member(object):
    next_id = 1

    def __init__(self, name):
        self.name = name
        self.borrowed = 0
        self.id = Member.next_id
        Member.next_id += 1

    def borrow_book(self):
        if self.can_borrow():
            self.borrowed += 1
            return True
        return False

    def return_book(self):
        if self.borrowed > 0:
            self.borrowed -= 1
            return True
        return False

    def get_borrow_limit(self):
        return 3

    def can_borrow(self):
        return self.borrowed < self.get_borrow_limit()

    def __str__(self):
        return (
            "member:"
            + str(self.id)
            + ":"
            + str(self.name)
            + ":"
            + str(self.borrowed)
        )


class StudentMember(Member):
    def __init__(self, name, major):
        super().__init__(name)
        self.major = major

    def get_borrow_limit(self):
        return 5

    def __str__(self):
        return (
            "student:"
            + str(self.id)
            + ":"
            + str(self.name)
            + ":"
            + str(self.major)
            + ":"
            + str(self.borrowed)
        )


if __name__ == "__main__":
    print("=== Example 1 ===")
    m = Member("Amy")
    print(m)
    print(m.get_borrow_limit())
    print(m.can_borrow())

    print("\n=== Example 2 ===")
    s = StudentMember("Bob", "CS")
    print(s)
    print(s.get_borrow_limit())

    print("\n=== Example 3 ===")
    c = StudentMember("Carol", "EE")
    c.borrow_book()
    c.borrow_book()
    c.borrow_book()
    c.borrow_book()
    c.borrow_book()

    print(c.can_borrow())

    c.return_book()

    print(c.can_borrow())

    print("\n=== Class variable test ===")
    x = Member("David")
    y = StudentMember("Eva", "ME")
    print(x.id)
    print(y.id)
```
