### ① Check My Understanding

**Question 1 — Input Size and Worst Case**  
**True or False:** In linear search on a list with `n` elements, the worst-case running time is `O(n)` even if the target sometimes appears at the beginning.

**Model answer:** True.

**Reason:** The best case checks only the first element, but the worst case occurs when the target is absent or at the end. Then up to `n` elements must be examined. Big O is commonly used in this lecture to describe a tight upper bound for the worst case.

**Question 2 — Constant Factors and Dominant Terms**  
**True or False:** Since `1000n` has a larger coefficient than `n²`, the dominant term of `T(n) = n² + 1000n + 7` is `1000n`.

**Model first answer:** True.

**AI hint (model):** Try comparing `n²` and `1000n` when `n = 10`, `n = 1000`, and `n = 100000`. Which term keeps growing faster as `n` becomes very large?

**Model revised answer:** False.

**Reason:** The key is *asymptotic growth*, not which term is bigger for a small input. The ratio `n²/(1000n) = n/1000` grows without bound. Therefore `n²` eventually dominates and the tight asymptotic order is `O(n²)`. Multiplicative constants and lower-order terms do not change the order of growth.

**Question 3 — Sequential Loops**  
**True or False:** Two sequential loops that each run `n` times necessarily make a program `O(n²)`.

**Model first answer:** True.

**AI hint (model):** Do the iterations happen one *inside* the other, or does the second loop begin only after the first one finishes? Should we add `n + n` or multiply `n × n`?

**Model revised answer:** False.

**Reason:** Sequential work is added. Two independent loops of `n` iterations each take `O(n) + O(n) = O(2n) = O(n)`. Nested loops can require multiplication, but only after checking their ranges and actual work.

**Question 4 — Sorted Linear Search**  
**True or False:** When a list is sorted, a sequential search may return early when it reaches a value greater than the target, but its worst-case complexity is still `O(n)`.

**Model answer:** True.

**Reason:** Sorted order lets the algorithm stop early for some inputs. However, a search for a target larger than every list element can still require checking all `n` elements. An improved practical running time on some inputs does not necessarily improve worst-case asymptotic complexity.

**Question 5 — Nested Loops and Hidden Costs**  
**True or False:** If an outer loop runs `n` times and an inner loop runs exactly five times for every outer iteration, the running time is `O(n)` (assuming constant work inside).

**Model answer:** True.

**Reason:** The operation count grows like `5n`, which simplifies to `O(n)`. Merely seeing two `for` loops is not enough to conclude `O(n²)`; we need to inspect the loop bounds.

**Explanation:** Two `for` loops may be sequential or nested. Even with nested loops, one inner loop might run only a fixed number of times, resulting in linear rather than quadratic growth. The actual ranges and cost of the loop body matter.

```python
# Sequential: O(n)
for i in range(n):
    print(i)
for j in range(n):
    print(j)

# Nested, but still O(n): 5n operations
for i in range(n):
    for j in range(5):
        print(i, j)

# Nested with n iterations in each loop: O(n^2)
for i in range(n):
    for j in range(n):
        print(i, j)
```

**Why the solution works:**  
The outer loop chooses each possible first index `i`. For every `i`, the inner loop visits exactly those indices `j > i`. Thus every unordered pair of distinct indices appears once and only once. The `if` condition increments the counter precisely when the values sum to `target`, so the final count is the number of qualifying pairs.

**Time complexity:**  
Let `n = len(numbers)`. The inner loop runs `n - i - 1` times for each `i`. The total number of comparisons is

`(n - 1) + (n - 2) + ... + 1 + 0 = n(n - 1)/2`.

This is `(n² - n)/2`. The dominant term is `n²`, and we ignore multiplicative constants and lower-order terms, so the worst-case time complexity is **O(n²)** (in fact, Θ(n²)).

**Extra space complexity:**  
The algorithm only stores loop indices and one counter. It does not create a second list, so the auxiliary space complexity is **O(1)**.

## Final Program

Save the following code as **`w10.py`** (also provided as a separate file):

```python
classroom_note = "Count each index pair once, with i < j."


def count_target_pairs(numbers, target):
    count = 0
    for i in range(len(numbers)):
        for j in range(i + 1, len(numbers)):
            if numbers[i] + numbers[j] == target:
                count += 1
    return count

    for numbers, target, expected in cases:
        actual = count_target_pairs(numbers, target)
```
