3. 演算法前置作業的代價必須納入整體複雜度評估：未排序清單進行單次搜尋時，直接線性搜尋（$O(n)$）優於先排序後二分搜尋（$O(n \log n)$），只有在多次查詢（$k > \log n$）時預先排序才能被平攤。
4. 子集合生成問題受限於輸出規模下界（$\Omega(2^n)$），且問題規模折半不等於對數時間，若每層分支為 2（如 $T(n) = 2T(n/2) + O(1)$），葉節點數量為 $2^{\log_2 n} = n$，總時間依然是線性時間 $O(n)$。

AI-generated coding challenge title:

Find Minimum in Rotated Sorted Array（旋轉排序陣列中的極小值定位）

```python
def find_min_rotated(nums: list[int]) -> int:
    left, right = 0, len(nums) - 1

    while left < right:
        mid = (left + right) // 2

        if nums[mid] > nums[right]:
            left = mid + 1
        else:
            right = mid

    return nums[left]
```

⸻

### 2. My Initial Approach — Before AI Help

Before asking AI for hints, briefly describe how you planned to solve the problem.

My approach:

在區間的中間和右端點比較：如果中間元素大於右端點元素（`nums[mid] > nums[right]`），代表樞紐點（Pivot）與最小值必定落在右半部，且 `mid` 本身絕不可能是最小值，因此將左邊界更新為 `left = mid + 1`；反之若不大於，則代表右半部為單調遞增，最小值必在左半部或恰為 `mid` 本身，故收縮右邊界為 `right = mid`。反覆折半收縮直到 `left` 與 `right` 重合於最小值位置。

The most useful hint/question from AI was:

獨立分析並完成實作。深入思考了邊界更新時 `left = mid + 1` 與 `right = mid` 的不對稱性：若 `nums[mid] > nums[right]` 成立，則 `mid` 絕對大於某個存在於陣列中的元素，故 `mid` 本身絕不可能是最小值；而當不成立時，`mid` 仍有可能是全陣列最小值，必須保留在候選範圍中。

It helped me realize that:

二分搜尋不僅適用於全域嚴格排序陣列，只要在區間中能找到確定性的「淘汰半邊」條件，即可在對數時間內逼近目標極值。
