Now: I understand…

經過今天的討論與診斷後，我清楚掌握了：
1. **選擇排序的比較次數恆定為 $\Theta(n^2)$**：選擇排序每一輪必須窮舉未排序後綴的所有元素才能確定最小值，因此不論輸入陣列初始是否已經排序，其比較次數永遠為 $\frac{n(n-1)}{2} = \Theta(n^2)$，無法像氣泡排序般藉由提早終止旗標在最佳情況達到 $O(n)$。
2. **長距離跨越交換破壞穩定性**：氣泡排序只進行相鄰元素交換，故能自然維持相同鍵值的相對順序（穩定排序）；而選擇排序是將最小值與前綴末端進行跨越式長距離交換，會破壞相同鍵值元素的相對先後順序（不穩定排序）。
3. **合併排序的輔助空間下界**：即使透過傳遞索引邊界 `(low, mid, high)` 避免清單切片複製，在合併（Merge）兩已排序子區間時，仍必須配置大小為 $O(n)$ 的暫存緩衝區來依序存放比對結果，因此其額外輔助空間複雜度始終為 $\Theta(n)$，而非僅由呼叫堆疊決定的 $O(\log n)$。
4. **決策樹模型下界僅規範最差與平均情況**：比較型排序的決策樹樹高下界 $\lceil \log_2(n!) \rceil = \Omega(n \log n)$ 描述的是根節點至葉節點的最長路徑（最差情況）；而在最佳情況（最短路徑）下，驗證已排序陣列僅需 $n-1$ 次相鄰比對，如插入排序或優化後的氣泡排序皆能達到 $O(n)$。
5. **合併平手時的取左原則**：合併排序在雙指標比較時，遇到鍵值相等（`left[i] == right[j]`）必須嚴格優先將左側元素推入結果串列（即條件應為 `left[i] <= right[j]`），才能避免後方元素超前，確保穩定性。

Merge K Sorted Lists via Divide-and-Conquer（分治法合併 K 個已排序串列）

```python
def merge_two_sorted(list1: list[int], list2: list[int]):
    # two pointer merging
    i, j = 0, 0
    merged = []
    while i < len(list1) and j < len(list2):
        if list1[i] < list2[j]:
            merged.append(list1[i])
            i += 1
        else:
            merged.append(list2[j])
            j += 1
    merged.extend(list1[i:])
    merged.extend(list2[j:])
    return merged


def merge_k_sorted(lists: list[list[int]]):
    n = len(lists)
    if n == 0:
        return []
    if n == 1:
        return lists[0]
    mid = n // 2
    left = merge_k_sorted(lists[:mid])
    right = merge_k_sorted(lists[mid:])
    return merge_two_sorted(left, right)
```

My approach:

若採用樸素的順序迭代合併，每次將當前串列與累積串列合併，第 $i$ 次合併長度為 $O(i \cdot m)$，總時間會累積退化至 $O(k \cdot N) \approx O(N^2)$。因此必須採用分治法（Divide and Conquer），將 $k$ 個串列由中點對半折半遞迴切分，最後自底向上兩兩合併，使整體遞迴樹的高度維持在 $\lceil \log_2 k \rceil$，每一層的總合併代價皆為 $O(N)$，使總時間複雜度壓制在 $O(N \log k)$。
