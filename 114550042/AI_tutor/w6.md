### ② My Misconception

Before: I thought…

在過去對於時間複雜度的理解較為直觀，且對漸近下界 Big $\Omega$（Big Omega）等符號的數學意義與應用情境理解較少，有時容易將最差情況（Worst-Case）與 Big O 符號混為一談。

⸻

Now: I understand…

經過今天的討論與診斷後，我更深入理解了：
1. 輸入情境（Best-case / Worst-case / Average-case）與漸近符號（$O, \Omega, \Theta$）是不同維度的概念：前者描述不同特徵的輸入資料所對應的執行時間函式；後者則是數學上的漸近上界、下界與緊確界限。因此即使在「最佳情況」下，依然可以使用 Big O（例如線性搜尋的最佳情況為 $O(1)$）。
2. Big O 本質上代表漸近上界（Asymptotic Upper Bound），因此若一演算法最差情況為 $O(n)$，在嚴格數學定義下亦為 $O(n^2)$。
3. 漸近分析描述的是輸入規模趨近無窮大（$n \to \infty$）時的增長速率。在較小規模的 $n$ 下，常數因子與低次項的影響可能使 $O(n^2)$ 演算法的實際執行時間快於 $O(n)$ 演算法。
4. 複雜度分析不能只看表面的一層迴圈，必須注意語法隱含的內部操作成本（例如清單走訪 `item not in list` 與切片 `L[1:]` 產生複製皆具有 $O(k)$ 的時間成本，容易導致總體時間複雜度退化為 $O(n^2)$）。

AI-generated coding challenge title:

Efficient Sorted Lists Intersection（已排序雙清單的高效交集合併）

```python
def intersect_sorted(nums1: list[int], nums2: list[int]):
    i, j = 0, 0
    intersection: list[int] = []

    # two pointer merge
    while i < len(nums1) and j < len(nums2):
        if nums1[i] < nums2[j]:
            i += 1
        elif nums1[i] > nums2[j]:
            j += 1
        else:
            intersection.append(nums1[i])
            i += 1
            j += 1

    return intersection
```
