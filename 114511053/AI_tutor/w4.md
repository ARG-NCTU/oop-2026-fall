## Part A — 觀念複習

### 1. Class 與 Object

題目：

```python
class Student:
    def __init__(self, name):
        self.name = name

s1 = Student("Alice")
s2 = Student("Bob")
```

我的回答：

```text
Student → class
s1      → object
s2      → object
```

其中：

```python
Student
```

是一個 class，可以把它想成建立物件的模板或藍圖。

而：

```python
s1 = Student("Alice")
s2 = Student("Bob")
```

會根據 `Student` 這個 class 建立兩個不同的 object，也可以稱為 instance。

因此：

```python
s1.name
```

為：

```text
Alice
```

而：

```python
s2.name
```

為：

```text
Bob
```

雖然 `s1` 和 `s2` 都是由同一個 class 建立，但仍然是兩個不同的 object。

### 2. `self` 的意義

題目：

```python
class Student:
    def __init__(self, name):
        self.name = name

    def introduce(self):
        return "I am " + self.name

s1 = Student("Alice")
print(s1.introduce())
```

輸出：

```text
I am Alice
```

我理解 `self` 代表：

> 現在正在呼叫這個 method 的 object。

因此當：

```python
s1.introduce()
```

被呼叫時，method 裡面的：

```python
self
```

代表的就是：

```python
s1
```

所以：

```python
self.name
```

可以理解成：

```python
s1.name
```

因此最後得到：

```text
I am Alice
```

我目前的理解可以簡化成：

```text
self = 目前正在操作的 instance
```

### 3. Instance Attribute

題目：

```python
class Counter:
    def __init__(self):
        self.value = 0

    def add(self):
        self.value += 1

c1 = Counter()
c2 = Counter()

c1.add()
c1.add()
c2.add()

print(c1.value)
print(c2.value)
```

我的答案：

```text
2
1
```

因為：

```python
self.value
```

是 instance attribute。

`c1` 和 `c2` 是不同的 object，所以各自擁有自己的 `value`。

一開始：

```text
c1 → value = 0
c2 → value = 0
```

執行：

```python
c1.add()
c1.add()
```

之後：

```text
c1 → value = 2
c2 → value = 0
```

最後：

```python
c2.add()
```

才會得到：

```text
c1 → value = 2
c2 → value = 1
```

因此對 `c1` 做操作不會自動修改 `c2` 的 instance attribute。

### 4. Class Attribute 與 Instance Attribute

題目：

```python
class Student:
    school = "NYCU"

    def __init__(self, name):
        self.name = name

s1 = Student("Alice")
s2 = Student("Bob")

print(s1.school)
print(s2.school)
```

輸出：

```text
NYCU
NYCU
```

其中：

```python
school = "NYCU"
```

是 **class attribute**。

它定義在 class 本身，因此所有 instance 都可以透過 class 取得這個值。

可以理解成：

```text
Student.school → "NYCU"
s1.school      → "NYCU"
s2.school      → "NYCU"
```

而：

```python
self.name = name
```

是 **instance attribute**。

所以：

```text
s1.name → "Alice"
s2.name → "Bob"
```

兩者的主要差別可以整理成：

```text
Class Attribute
→ 定義在 class
→ 多個 object 可以共用

Instance Attribute
→ 定義在特定 instance
→ 每個 object 可以有不同的值
```

例如所有學生可能都屬於同一間學校，但每個學生有自己的名字。

### 5. Method 修改 Object 的狀態

題目：

```python
class BankAccount:
    def __init__(self, balance):
        self.balance = balance

    def deposit(self, amount):
        self.balance += amount

account = BankAccount(100)
account.deposit(50)

print(account.balance)
```

我的答案：

```text
150
```

原本：

```text
account.balance = 100
```

呼叫：

```python
account.deposit(50)
```

之後：

```python
self.balance += amount
```

會直接修改 `account` 這個 object 本身的狀態。

因此：

```text
100 + 50 = 150
```

這裡的 `deposit()` 並不是建立新的 object，而是在修改原本 object 的 attribute。

## Challenge the AI

AI 說：

> If two objects are created from the same class, changing an attribute of one object will automatically change the same attribute of the other object, because both objects come from the same class.

我判斷這個說法是：

```text
有條件才正確
```

因為必須先判斷這個 attribute 是：

```text
instance attribute
```

還是：

```text
class attribute
```

例如：

```python
class Student:
    def __init__(self, name):
        self.name = name

s1 = Student("Alice")
s2 = Student("Bob")

s1.name = "Carol"
```

最後：

```text
s1.name → "Carol"
s2.name → "Bob"
```

因為 `name` 是 instance attribute，所以修改 `s1.name` 不會影響 `s2.name`。

但是如果：

```python
class Student:
    school = "NYCU"
```

然後修改：

```python
Student.school = "NTHU"
```

那麼沒有自行覆蓋 `school` 的 instance，都會透過 class 看到新的值。

所以 AI 原本的說法太籠統。

比較精確的說法應該是：

> Instance attributes are normally independent for each object, while class attributes are shared through the class unless an instance defines an attribute with the same name.

這次的 Challenge the AI 讓我更清楚分辨 class attribute 與 instance attribute。

## Part B — Coding Challenge

### 題目：Rectangle Class

建立一個：

```python
class Rectangle:
    ...
```

要求：

```text
1. 建立 object 時輸入 width 和 height
2. area() 回傳矩形面積
3. perimeter() 回傳矩形周長
```

例如：

```python
r = Rectangle(3, 4)

print(r.area())
print(r.perimeter())
```

預期輸出：

```text
12
14
```

---

## 我的解法

```python
class Rectangle:
    def __init__(self, width, height):
        self.width = width
        self.height = height

    def area(self):
        return self.width * self.height

    def perimeter(self):
        return 2 * (self.width + self.height)
```

測試：

```python
r = Rectangle(3, 4)

print(r.area())
print(r.perimeter())
```

輸出：

```text
12
14
```

---

## 程式結構分析

在這個程式中：

```python
Rectangle
```

是一個 class。

```python
r
```

是一個 object / instance。

```python
self.width
self.height
```

是 instance attributes。

```python
area()
perimeter()
```

則是 methods。

當執行：

```python
r.area()
```

時，`area()` 裡面的：

```python
self
```

代表：

```python
r
```

所以：

```python
self.width
```

就是：

```python
r.width
```

而：

```python
self.height
```

就是：

```python
r.height
```

---

## Complexity Analysis

`area()`：

```python
def area(self):
    return self.width * self.height
```

只有一次乘法，因此：

```text
Time Complexity = O(1)
```

`perimeter()`：

```python
def perimeter(self):
    return 2 * (self.width + self.height)
```

也只有固定次數的加法與乘法，因此：

```text
Time Complexity = O(1)
```

這兩個 method 的運算次數不會因為其他資料量增加而增加。

## Reflection

這週複習後，我比較清楚以下觀念：

- Class 是建立 object 的模板。
- Object / instance 是依照 class 建立出來的實體。
- `self` 代表目前正在操作的 object。
- `self.attribute` 可以保存 object 自己的狀態。
- Instance attribute 可以讓不同 object 保存不同資料。
- Class attribute 是定義在 class 上的共享資料。
- 修改一個 object 的 instance attribute，通常不會影響其他 object。
- 修改 class attribute 時，多個 instance 可能都會看到新的值。
- Method 可以讀取或修改 object 的狀態。
- OOP 可以把資料與操作資料的方法放在同一個 class 中。
- `Rectangle.area()` 與 `Rectangle.perimeter()` 都是 `O(1)`。

這次前面的基本 OOP 題目大多可以直接判斷正確，但 Challenge the AI 讓我注意到，不能只說「同一個 class 建立的 object 會不會互相影響」，而必須進一步區分 class attribute 和 instance attribute。

我目前可以把 OOP 的基本結構理解成：

```text
Class
  ↓ 建立
Object / Instance
  ├─ Attributes → 儲存狀態
  └─ Methods    → 操作狀態
```

這也讓我比較能理解為什麼 OOP 適合把相關的資料和功能整理在一起。
