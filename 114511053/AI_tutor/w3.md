## Part A — 觀念複習

### 1. Runtime Error：除以 0

題目：

```python
def divide(a, b):
    return a / b

print(divide(10, 0))
```

我判斷這會在執行時發生除以 0 的錯誤。

更精確的錯誤名稱是：

```text
ZeroDivisionError
```

這屬於 **runtime error**，因為程式語法本身沒有錯，而是在實際執行到：

```python
a / b
```

時才發生錯誤。

如果希望 `b == 0` 時不要讓程式直接中止，可以先判斷：

```python
def divide(a, b):
    if b == 0:
        return None

    return a / b
```

也可以使用 exception handling：

```python
def divide(a, b):
    try:
        return a / b
    except ZeroDivisionError:
        return None
```

兩種方法的概念不同：

```text
if           → 事先避免錯誤發生
try/except   → 發生指定 exception 後再處理
```

### 2. `try / except`

題目：

```python
def convert(s):
    try:
        x = int(s)
        return x * 2
    except ValueError:
        return -1
```

執行：

```python
print(convert("12"))
print(convert("abc"))
```

我的答案：

```text
24
-1
```

因為：

```python
int("12")
```

可以成功轉換成整數 `12`，所以：

```text
12 * 2 = 24
```

但是：

```python
int("abc")
```

無法轉換成整數，因此 Python 會產生：

```text
ValueError
```

接著被：

```python
except ValueError:
```

捕捉，最後回傳 `-1`。

因此 `except ValueError` 只負責處理 `ValueError`，不是所有種類的錯誤。

### 3. Assertion

題目：

```python
def get_average(total, count):
    assert count > 0
    return total / count
```

執行：

```python
print(get_average(100, 4))
print(get_average(100, 0))
```

第一個結果為：

```text
25.0
```

第二個會在：

```python
assert count > 0
```

失敗，產生：

```text
AssertionError
```

我理解 `assert` 比較適合用來確認：

> 按照程式本身的設計邏輯，某個條件應該永遠成立。

例如：

```python
assert index >= 0
assert len(items) > 0
assert result is not None
```

因此 `assert` 比較接近 debugging 或 internal sanity check。

如果是一般使用者可能輸入錯誤資料，通常比較適合使用：

```text
if
try / except
```

來處理。

### 4. Logic Error

題目：

```python
def is_even(n):
    return n % 2 == 1
```

執行：

```python
print(is_even(4))
```

結果會是：

```text
False
```

但是函式名稱 `is_even()` 的目的應該是判斷偶數，因此正確條件應該是：

```python
return n % 2 == 0
```

這是一個 **logic error**。

程式：

- 沒有 syntax error
- 不會 crash
- 可以正常執行
- 但是答案不符合預期

我認為 logic error 通常比 syntax error 更難發現，因為程式不會主動跳出錯誤訊息，只能透過測試或檢查結果發現問題。

### 5. Unit Test 與 Edge Case

正確版本：

```python
def is_even(n):
    return n % 2 == 0
```

測試：

```python
assert is_even(4) == True
assert is_even(7) == False
assert is_even(0) == True
```

只測：

```python
is_even(4)
```

並不能代表整個函式一定正確。

因為還需要測試不同種類的輸入，例如：

```text
偶數
奇數
0
負數
```

例如：

```python
assert is_even(4) == True
assert is_even(7) == False
assert is_even(0) == True
assert is_even(-2) == True
```

其中 `0` 可以視為一個比較特殊的 edge case。

數學上：

```text
0 = 2 × 0
```

所以 0 是偶數：

```python
0 % 2 == 0
```

## Challenge the AI

AI 說：

> If a program passes all of our unit tests, then the program is guaranteed to be correct.

我判斷這個說法是錯的。

即使程式通過目前所有 unit tests，也只能表示：

> 我們目前想到並寫出的測試案例都有通過。

並不能保證所有可能的輸入都正確。

例如我們可能只測：

```python
assert is_even(4) == True
assert is_even(7) == False
assert is_even(0) == True
```

但如果程式在：

```text
負數
極端數值
其他特殊輸入
```

有問題，而我們沒有寫對應測試，就可能仍然存在 bug。

因此比較正確的說法是：

> Passing all current unit tests increases confidence in correctness, but does not prove that the program is completely correct.

## Part B — Coding Challenge

### 題目：Safe Average

撰寫：

```python
def safe_average(nums):
    ...
```

要求：

- `nums` 是一個 list
- 如果 list 為空，回傳 `None`
- 否則回傳平均值
- 不可以因為除以 0 而讓程式 crash

例如：

```python
safe_average([10, 20, 30])   # 20.0
safe_average([])             # None
```

---

## 我的初始解法

我一開始寫：

```python
def safe_average(nums):
    if(nums == []) return None

    total = 0
    l = 0

    for i in nums:
        l += 1
        total += i

    return total / l
```

我的整體邏輯是：

1. 先檢查 list 是否為空
2. 計算總和與元素數量
3. 用總和除以數量

邏輯本身沒有問題，但是：

```python
if(nums == []) return None
```

有 Python syntax error。

正確寫法應為：

```python
if nums == []:
    return None
```

也可以使用更常見的 Python 寫法：

```python
if not nums:
    return None
```

---

## 修正版

```python
def safe_average(nums):
    if not nums:
        return None

    total = 0
    l = 0

    for i in nums:
        l += 1
        total += i

    return total / l
```

這樣在輸入空 list 時：

```python
safe_average([])
```

會直接回傳：

```text
None
```

因此不會發生：

```text
ZeroDivisionError
```

## Error Type 比較

這次練習讓我更清楚三種錯誤的差別：

```text
Syntax Error
→ 程式語法不合法
→ 例如 if 後少了 :

Runtime Error
→ 程式開始執行後才發生錯誤
→ 例如除以 0

Logic Error
→ 程式可以執行，但答案不符合預期
→ 通常沒有錯誤訊息
```

我這次的 `safe_average()` 初始版本就是：

```text
邏輯正確
但存在 Syntax Error
```

## Complexity Analysis

假設 `nums` 有 `n` 個元素。

程式中的：

```python
for i in nums:
```

會走過所有元素一次，因此：

```text
Time Complexity = O(n)
```

額外使用的變數只有：

```text
total
l
i
```

沒有另外建立會隨 `n` 增加的 list 或 dictionary，因此：

```text
Extra Space Complexity = O(1)
```

## Unit Test 設計

我為 `safe_average()` 思考了以下測試：

```python
assert safe_average([10, 20, 30]) == 20.0
assert safe_average([]) is None
assert safe_average([5]) == 5.0
assert safe_average([-10, 10]) == 0.0
```

這四個測試分別測試：

```text
[10, 20, 30]
→ 一般情況

[]
→ 空 list / edge case
→ 檢查 if not nums 是否有正常運作

[5]
→ 只有一個元素的情況

[-10, 10]
→ 有負數時是否仍能正確運算
```

我一開始認為第三個 `[5]` 可能可以刪掉，但後來理解只有一個元素也是有價值的特殊情況，因為程式有可能錯誤假設 list 至少包含兩個元素。

---

## PyTest

可以將測試寫成：

```python
def test_safe_average_normal():
    assert safe_average([10, 20, 30]) == 20.0


def test_safe_average_empty():
    assert safe_average([]) is None


def test_safe_average_single():
    assert safe_average([5]) == 5.0


def test_safe_average_negative():
    assert safe_average([-10, 10]) == 0.0
```

PyTest 可以自動找到以：

```text
test_
```

開頭的測試函式並執行。

如果四個測試全部成功，可能會看到：

```text
4 passed
```

但是這仍然只代表目前寫出的四個測試案例通過，不能代表程式在所有可能情況下完全正確。

## Debugging Practice

題目：

```python
def safe_average(nums):
    if not nums:
        return None

    total = 0

    for i in nums:
        total += i

    return total / (len(nums) - 1)
```

測試：

```python
assert safe_average([10, 20, 30]) == 20.0
```

會失敗。

我正確判斷這是一個：

```text
Logic Error
```

因為程式可以執行，但答案錯誤。

我第一眼也正確找到問題在：

```python
return total / (len(nums) - 1)
```

不過我一開始認為應該改成：

```python
len(nums) + 1
```

後來重新檢查平均值公式後發現，正確答案應該是完全不加也不減：

```python
return total / len(nums)
```

例如：

```text
nums = [10, 20, 30]

total = 60
len(nums) = 3

60 / 3 = 20
```

這讓我理解到 debugging 時，找到「可能有問題的那一行」之後，仍然需要重新確認公式或邏輯，而不能只直覺修改數值。

## Reflection

這週複習後，我比較清楚以下觀念：

- Syntax error、runtime error 與 logic error 的差別
- `ZeroDivisionError` 是 runtime error
- `try / except` 可以處理特定 exception
- `assert` 適合檢查程式內部應該成立的條件
- Logic error 不一定會產生任何錯誤訊息
- Testing 的目的之一是找出程式不會主動回報的 logic error
- Unit test 應該包含 normal case 與 edge case
- 通過所有目前的 unit tests 並不能證明程式完全正確
- PyTest 可以自動執行 `test_` 開頭的測試
- Debugging 時除了找出可疑程式碼，也需要重新確認真正的公式與邏輯
- `safe_average()` 的時間複雜度是 `O(n)`，額外空間為 `O(1)`

我這次比較容易出錯的地方不是主要邏輯，而是一些細節，例如 Python `if` 的語法，以及找到錯誤位置後仍可能把正確公式改錯。因此之後除了思考整體演算法，也需要利用測試去確認修改後的結果是否真的正確。
