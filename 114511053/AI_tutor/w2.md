## Part A — 觀念複習

### 1. Recursion 與 Base Case

題目：

```python
def mystery(n):
    if n == 0:
        return 1
    return n * mystery(n - 1)

print(mystery(4))
```

我的回答是：

```text
24
```

因為這個函式實際上是在計算：

```text
4!
```

展開後為：

```text
mystery(4)
= 4 * mystery(3)
= 4 * 3 * mystery(2)
= 4 * 3 * 2 * mystery(1)
= 4 * 3 * 2 * 1 * mystery(0)
= 4 * 3 * 2 * 1 * 1
= 24
```

其中：

```python
if n == 0:
    return 1
```

是 recursion 的 **base case**。

遞迴一定需要停止條件，否則會繼續：

```text
mystery(4)
→ mystery(3)
→ mystery(2)
→ ...
→ mystery(0)
→ mystery(-1)
→ mystery(-2)
→ ...
```

最後因為遞迴層數太深而出現：

```text
RecursionError
```

另外，`return 1` 也很合理，因為：

```text
0! = 1
```

而且乘以 1 不會改變前面累積的結果。

### 2. Recursion 的執行順序與 Call Stack

題目：

```python
def f(n):
    if n == 0:
        print("base")
        return

    print("before", n)
    f(n - 1)
    print("after", n)

f(3)
```

我預測的輸出為：

```text
before 3
before 2
before 1
base
after 1
after 2
after 3
```

結果正確。

遞迴呼叫往下時：

```text
f(3)
 └─ f(2)
     └─ f(1)
         └─ f(0)
```

每一層函式都會等待下一層執行完成。

當 `f(0)` 結束後，才會開始往回：

```text
f(0) 結束
→ 回到 f(1)，執行 after 1
→ 回到 f(2)，執行 after 2
→ 回到 f(3)，執行 after 3
```

這讓我更清楚理解 recursion 不只有「一直往下呼叫」，還有「一層一層回傳」的過程，而尚未完成的函式會留在 call stack 中。

### 3. Dictionary 的修改與新增

題目：

```python
d = {
    "apple": 3,
    "banana": 5
}

d["apple"] += 2
d["orange"] = 4

print(d)
```

我的答案：

```python
{
    "apple": 5,
    "banana": 5,
    "orange": 4
}
```

其中：

```python
d["apple"] += 2
```

是在修改原本已存在的 key。

而：

```python
d["orange"] = 4
```

因為 `"orange"` 原本不存在，所以是在新增一組 key-value pair。

Dictionary 可以想成：

```text
key → value
```

例如：

```text
"apple"  → 5
"banana" → 5
"orange" → 4
```

### 4. Dictionary 查找與 `get()`

題目：

```python
d = {
    "a": 1,
    "b": 2
}

print(d["c"])
```

我的回答是會出現：

```text
KeyError
```

因為 `"c"` 並不存在。

另外可以使用：

```python
d.get(...)
```

差別如下：

```python
d[key]          # key 不存在 → KeyError
d.get(key)      # key 不存在 → None
d.get(key, 0)   # key 不存在 → 0
```

例如：

```python
count = {}

for x in ["a", "b", "a"]:
    count[x] = count.get(x, 0) + 1
```

最後會得到：

```python
{"a": 2, "b": 1}
```

因此 `get(key, 0)` 很適合拿來做計數。

### 5. Recursion 與 Dictionary 結合

題目：

```python
def count_chars(s, i=0, result=None):
    if result is None:
        result = {}

    if i == len(s):
        return result

    c = s[i]
    result[c] = result.get(c, 0) + 1

    return count_chars(s, i + 1, result)
```

執行：

```python
print(count_chars("abaca"))
```

我預測的結果：

```python
{'a': 3, 'b': 1, 'c': 1}
```

結果正確。

我一開始把：

```python
if i == len(s):
```

理解成「負責遍歷字串的部分」。

後來才發現這個說法不夠精確。

真正的功能分別是：

```text
i = 0           → 初始位置
i + 1           → 往下一個字元移動
i == len(s)     → 停止條件
```

所以真正讓 recursion 往下一個字元前進的是：

```python
return count_chars(s, i + 1, result)
```

而：

```python
if i == len(s):
    return result
```

只是 base case。

另外：

```python
result[c] = result.get(c, 0) + 1
```

是因為如果直接寫：

```python
result[c] += 1
```

第一次遇到某個字元時，因為 key 還不存在，就會出現 `KeyError`。

---

## My Misconception

這次我其中一個觀念錯誤是：

> 我一開始以為 `i == len(s)` 是負責遍歷字串的部分。

後來理解到：

```python
i == len(s)
```

其實只是在判斷什麼時候停止 recursion。

真正讓程式往下一個位置移動的是：

```python
i + 1
```

可以整理成：

```text
初始值         → i = 0
前進方式       → i + 1
停止條件       → i == len(s)
```

這讓我更清楚 recursion 中「前進」和「停止」其實是兩個不同的概念。

## Challenge the AI

AI 提出：

> 可以把 `result=None` 改成：
>
> ```python
> def count_chars(s, i=0, result={}):
> ```
>
> 因為每次呼叫函式時都會重新建立一個新的空 dictionary。

我判斷這個說法是錯的。

Python 中 mutable default argument，例如：

```python
result={}
```

不是每次呼叫函式時重新建立，而是在函式被定義時建立一次，之後的呼叫可能會共用同一個 dictionary。

例如：

```python
def add_item(x, result={}):
    result[x] = result.get(x, 0) + 1
    return result

print(add_item("a"))
print(add_item("b"))
```

可能會得到：

```text
{'a': 1}
{'a': 1, 'b': 1}
```

因為第二次呼叫仍然使用第一次的 dictionary。

因此比較安全的寫法是：

```python
def count_chars(s, i=0, result=None):
    if result is None:
        result = {}
```

這樣每一次新的最外層呼叫，才會建立新的 dictionary。

## Part B — Coding Challenge

### 題目：Word Frequency

撰寫：

```python
def word_frequency(words):
    ...
```

輸入一個字串 list，計算每個單字出現的次數，並使用 dictionary 回傳。

例如：

```python
["apple", "banana", "apple", "orange", "banana", "apple"]
```

預期輸出：

```python
{
    "apple": 3,
    "banana": 2,
    "orange": 1
}
```

限制：

- 必須使用 dictionary
- 不使用 `collections.Counter`

---

## 我的解法

```python
def word_frequency(words):
    freq_dict = {}

    for word in words:
        freq_dict[word] = freq_dict.get(word, 0) + 1

    return freq_dict


words = ["apple", "banana", "apple", "orange", "banana", "apple"]
print(word_frequency(words))
```

輸出：

```text
{'apple': 3, 'banana': 2, 'orange': 1}
```

核心是：

```python
freq_dict[word] = freq_dict.get(word, 0) + 1
```

如果這個 word 第一次出現：

```text
0 + 1
```

如果已經出現過，就在原本的次數上加 1。

---

## Complexity Analysis

假設：

```text
n = words 中單字的總數
k = 不同單字的數量
```

迴圈：

```python
for word in words:
```

會執行 `n` 次。

我一開始以為 dictionary 查找可能會像 list 一樣，需要逐個搜尋，所以如果單字幾乎都不重複，整體可能會變成：

```text
O(n²)
```

後來才理解 Python dictionary 底層使用 hash table，因此 key lookup 與 insertion 平均情況通常是：

```text
O(1)
```

所以：

```python
freq_dict.get(word, 0)
```

平均為：

```text
O(1)
```

整體時間複雜度為：

```text
O(n)
```

空間方面，dictionary 最多會存 `k` 個不同單字，因此：

```text
Space Complexity = O(k)
```

最壞情況下，每個單字都不同：

```text
k = n
```

所以 worst case 為：

```text
O(n)
```

## Data Structure 比較

這次也比較了 list 與 dictionary 的 membership test。

如果：

```python
"apple" in words
```

其中 `words` 是 list，需要逐個比較，因此：

```text
O(n)
```

如果：

```python
"apple" in freq_dict
```

其中 `freq_dict` 是 dictionary，平均可以透過 hashing 查找，因此：

```text
O(1)
```

整理如下：

```text
list:  x in L → O(n)
dict:  x in d → O(1) average
set:   x in s → O(1) average
```

這讓我理解到，同樣是「查某個東西在不在」，時間複雜度會因底層資料結構不同而有很大差異。

## Recursion 的 Complexity

題目：

```python
def countdown(n):
    if n == 0:
        return

    print(n)
    countdown(n - 1)
```

呼叫過程：

```text
countdown(n)
→ countdown(n - 1)
→ countdown(n - 2)
→ ...
→ countdown(1)
→ countdown(0)
```

因此時間複雜度是：

```text
O(n)
```

另外，每一層尚未完成的 recursive call 都會留在 call stack 中，所以最多會有約 `n` 層：

```text
Space Complexity = O(n)
```

相比之下，如果改用：

```python
for i in range(n):
    print(i)
```

時間複雜度同樣是：

```text
O(n)
```

但額外空間通常只有：

```text
O(1)
```

因此即使 recursion 和 iteration 的時間複雜度相同，空間複雜度仍可能不同。

## Reflection

這週複習後，我比較清楚以下觀念：

- Recursion 必須有 base case。
- Recursive call 會先一路往下，再從 call stack 一層一層返回。
- Base case 是停止條件，不是負責讓 recursion 前進的部分。
- Dictionary 使用 key-value pair 儲存資料。
- `d[key]` 在 key 不存在時會產生 `KeyError`。
- `d.get(key, default)` 可以處理不存在的 key。
- Mutable default argument 可能會讓不同函式呼叫共用同一個物件。
- Python dictionary 使用 hash table，因此 key lookup 和 insertion 平均是 `O(1)`。
- List membership 平均需要 `O(n)`，而 dictionary 和 set 通常是 `O(1)` average。
- Recursion 和 iteration 即使時間複雜度一樣，空間複雜度可能不同。

我這次最需要加強的是 Big-O 與資料結構的連結。我原本會直覺認為資料很多時，dictionary 查找也需要逐個搜尋，但後來理解真正的複雜度要看底層資料結構，而不是只看資料數量。
