## Part B: LeetCode-style Lecture Code Transfer

### 1. Today's Challenge

**Core concept from today's OCW lecture:**

每一步把搜尋範圍砍半，複雜度是 O(log n)（bisection search），以及複製 list 會讓 O(log n) 變成 O(n) 的陷阱。

**AI-generated coding challenge title:** 整數平方根與二分搜尋（Integer Square Root）

- `int_sqrt(n)`：回傳最大的整數 `r`，使 `r * r <= n`，不能用 `math.sqrt`；`n` 是負數時觸發 `AssertionError`
- `first_at_least(L, x)`：在已排序的 `L` 裡，找第一個 `>= x` 的 index，找不到就回傳 `len(L)`
- 兩個都要是 O(log n)

### 2. My Initial Approach — Before AI Help

**My approach:**

在 0 到 n 之間做二分搜尋：每次取 `mid`，`mid * mid <= n` 代表答案至少是 `mid`，就往右半邊找；否則往左半邊找。每次範圍砍半，所以是 O(log n)，比從 0 一個一個試的 O(√n) 快。

**The most useful hint/question from AI was:**

「如果搜尋範圍寫成 `[low, high) = [0, n)`，那 n = 1 時會發生什麼事？」

**It helped me realize that:**

1. n = 1 時範圍只有 `{0}`，答案 1 根本不在範圍裡，會錯誤地回傳 0。所以上界要改成 `n + 1`，搜尋範圍是 `[0, n + 1)`。

### 4. My Revision

- [ ] No

**What did you change, and why?**

1. 搜尋範圍改成 `low, high = 0, n + 1`，讓 n = 0、n = 1 也包含在範圍內。
2. 迴圈條件寫成 `while high - low > 1`，並保持「`low` 一定符合 `low * low <= n`、`high` 一定不符合」，結束時 `low` 就是答案。
3. `first_at_least` 用同樣的想法，但範圍是 `[0, len(L)]`，找不到時才能回傳 `len(L)`。
4. 全程只傳 index，不切 list，避免 Part A 第 3 題的 O(n) 陷阱。

### 5. Verification

**My final program:**（完整程式見 `w7.py`）

```python
def int_sqrt(n):
    assert n >= 0, "n cannot be negative"
    low, high = 0, n + 1
    while high - low > 1:
        mid = (low + high) // 2
        if mid * mid <= n:
            low = mid
        else:
            high = mid
    return low


def first_at_least(L, x):
    low, high = 0, len(L)
    while low < high:
        mid = (low + high) // 2
        if L[mid] < x:
            low = mid + 1
        else:
            high = mid
    return low
```
