## Part B: LeetCode-style Lecture Code Transfer

### 1. Today's Challenge

**Core concept from today's OCW lecture:**

merge sort 的 divide and conquer：切一半、各自遞迴排序、再用 O(n) 的 merge 合併，整體 O(n log n)。

**AI-generated coding challenge title:** 計算逆序對（Count Inversions）

- inversion 是一對位置 `(i, j)`，其中 `i < j` 且 `L[i] > L[j]`
- `sort_and_count(L)`：回傳 `(排序後的新 list, inversion 數量)`，要 O(n log n)，而且不能改到原本的 `L`
- 例：`[2, 4, 1, 3, 5]` 有 3 對：(2,1)、(4,1)、(4,3)

### 2. My Initial Approach — Before AI Help

**My approach:**

改 merge sort，邊排序邊數：

1. 把 list 切成左右兩半，各自遞迴，回傳排好的 list 和各自內部的 inversion 數。
2. merge 時，如果右邊的元素先被放進結果，就代表它比左邊的某些元素小，這時要算 inversion。
3. 總數 = 左半內部 + 右半內部 + merge 時跨兩半的數量。

不確定的是：第 2 步遇到右邊比較小的時候，到底要加多少。

**The most useful hint/question from AI was:**

「merge 時，如果右邊目前的元素比左邊目前的元素小，左邊還剩 k 個元素沒放。這時 inversion 要加多少？」我答不出來，AI 解釋了答案。

**It helped me realize that:**

1. 要加 k，不是加 1。左半邊已經排好序，右邊這個元素比左邊目前這個小，就一定比左邊剩下的 k 個都小，一次會形成 k 對 inversion。用 `len(left) - i` 就能直接算出來，不需要一個一個比。
2. 比較時要用 `left[i] <= right[j]`，相等的時候先放左邊，這樣相同的值才不會被算成 inversion。

**What did you change, and why?**

1. 右邊元素先放進結果時，`count += len(left) - i`。
2. 比較條件用 `<=`，讓相等的值不算 inversion。
3. 用 `L[:mid]` 切出新的 list 再遞迴，原本的 `L` 不會被修改；`len(L) < 2` 時回傳 `L[:]` 這個副本。
4. 另外寫一個兩層迴圈的 `count_inversions_slow` 當作標準答案，用隨機測資比對。

### 5. Verification

**My final program:**（完整程式見 `w8.py`）

```python
def merge_and_count(left, right):
    result = []
    i, j, count = 0, 0, 0
    while i < len(left) and j < len(right):
        if left[i] <= right[j]:
            result.append(left[i])
            i += 1
        else:
            result.append(right[j])
            count += len(left) - i
            j += 1
    result.extend(left[i:])
    result.extend(right[j:])
    return result, count


def sort_and_count(L):
    if len(L) < 2:
        return L[:], 0
    mid = len(L) // 2
    left, a = sort_and_count(L[:mid])
    right, b = sort_and_count(L[mid:])
    merged, c = merge_and_count(left, right)
    return merged, a + b + c
```
