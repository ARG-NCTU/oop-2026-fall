### 1. Today's Challenge

**Core concept from today's OCW lecture:**

用 `try` / `except` 只處理特定種類的 exception、在資料真的有問題時自己 `raise`，以及用 `assert` 檢查 function 的假設（課堂的 `get_ratios` 和 `avg`）。

**AI-generated coding challenge title:** 穩健的成績平均（Robust Score Average）

`raw` 是助教手動輸入的字串 list，例如 `["90", "85.5", "abs", "70"]`。寫 `average_score(raw)` 回傳有效成績的平均：

- 不能轉成數字的項目直接跳過
- 數字不在 0 到 100 之間代表資料真的有錯，要 `raise ValueError`
- 沒有任何有效成績時回傳 `None`
- 不可以修改 `raw`

範例：`["90", "80", "70"]` → `80.0`；`["90", "abs", "70"]` → `80.0`；`[]` → `None`

**The most useful hint/question from AI was:**

「`["90", "abs", "70"]` 走到 `"abs"` 的時候，你的 `try` 包住的是整個 loop，那後面的 `"70"` 還會被處理到嗎？還有，`["101"]` 應該要 `raise ValueError`，你的 `except:` 會把它怎麼樣？」

**It helped me realize that:**

2. bare `except:` 會把我自己 `raise` 的 `ValueError` 也接走，超出範圍的成績就被默默跳過了。所以範圍檢查要放在 `try` 外面，而且 `except` 要指定種類。

**What did you change, and why?**

1. 把 `try` 縮小到只包 `float(entry)`，`except` 裡用 `continue` 跳過這一筆。
2. `except:` 改成 `except (ValueError, TypeError):`。`TypeError` 是 AI tutor 用 `[None, "60"]` 測出來之後才加的，`float(None)` 丟的不是 `ValueError`。
3. 範圍檢查移到 `try` 外面再 `raise ValueError`。
4. 個數是 0 時回傳 `None`，避免課堂上 `avg` 遇到空 list 的 `ZeroDivisionError`。
5. `"nan"` 可以被 `float()` 轉換但不是成績，這是 AI tutor 測出來的 edge case，用 `score != score` 判斷後跳過。這一行我自己想不到。

### 5. Verification

**My final program:**（見 `w3.py`）

```python
def average_score(raw):
    assert type(raw) == list, 'raw must be a list'

    total = 0.0
    count = 0
    for entry in raw:
        try:
            score = float(entry)
        except (ValueError, TypeError):
            continue
        if score != score:
            continue
        if score < 0 or score > 100:
            raise ValueError('score out of range: ' + str(entry))
        total += score
        count += 1

    if count == 0:
        return None
    return total / count
```
