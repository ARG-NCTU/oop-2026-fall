## Part B: LeetCode-style Lecture Code Transfer

### 1. Today's Challenge

**Core concept from today's OCW lecture:**

list 是 mutable，function 收到的是同一個 list 的 alias，所以可以在 function 裡直接修改呼叫者的 list；但是不能一邊 iterate 一邊修改同一個 list，要先 clone（課堂的 `remove_dups` 和 `remove_dups_new`）。另外用 tuple 一次回傳多個值（`quotient_and_remainder`）。

**AI-generated coding challenge title:** 清理修課名單（Purge the Roster）

`roster` 是修課學生名字的 list（名字可能重複），`dropped` 是退選的名字。寫 `purge_roster(roster, dropped)`：

- 直接在 `roster` 上把所有退選的名字移除（in place）
- 回傳 tuple `(移除的數量, 剩下的數量)`
- 不可以修改 `dropped`

範例：`roster = ["amy", "bob", "cat", "dan"]`、`dropped = ["bob"]` → 回傳 `(1, 3)`，`roster` 變成 `["amy", "cat", "dan"]`

### 2. My Initial Approach — Before AI Help

**My approach:**

1. 建立一個新的 list `result`，把不在 `dropped` 裡的名字 `append` 進去。
2. 最後寫 `roster = result`，讓 `roster` 變成清理後的結果。
3. 回傳 `(原本的長度 - len(result), len(result))`。

**The most useful hint/question from AI was:**

「function 裡的 `roster = result` 執行之後，呼叫者手上的那個 list 內容有變嗎？想一下 `hot = warm` 那個例子，`=` 做的是修改 object，還是讓名字改指到別的地方？」

**It helped me realize that:**

`roster = result` 只是讓 function 裡面的 `roster` 這個名字改指到新的 list，呼叫者原本的 list 完全沒有被動到，所以不符合 in place 的要求。要改到呼叫者的 list，必須用 `remove` 這種會 mutate 的 method。

改成在 loop 裡 `roster.remove(name)` 之後，AI tutor 又給了一個測資 `["amy", "bob", "bob", "cat"]`，結果只移掉一個 `"bob"`。這就是課堂 `remove_dups` 的 bug：移除一個 element 之後後面的往前補，loop 的 index 繼續往下走，剛好跳過下一個。

**What did you change, and why?**

1. 不再建立新的 list 再重新 assign，改成直接對 `roster` 呼叫 `remove`，這樣才會改到呼叫者的 list。
2. loop 改成 `for name in roster[:]:`，iterate 的是 clone，修改的是原本的 list，和 `remove_dups_new` 的 `L1_copy = L1[:]` 一樣。
3. 用一個 `removed` 變數記錄移除了幾個，最後回傳 `(removed, len(roster))`。

### 5. Verification

**My final program:**（見 `w1.py`）

```python
def purge_roster(roster, dropped):
    removed = 0
    for name in roster[:]:
        if name in dropped:
            roster.remove(name)
            removed += 1
    return (removed, len(roster))
```
