### ② My Misconception

**Before: I thought…**

1. memo 會「記住」之前算過的結果，所以只要加上 dictionary，recursion 就一定會變快。
2. 課堂上說 key 必須是 immutable，所以 tuple 一定可以當 key。

**Now: I understand…**

1. memo 只有在同一個 subproblem 會被重複算到的時候才有用，例如 `fib`。Towers of Hanoi 或 recursive 的 palindrome 檢查，每一次 call 都是不同的 subproblem，加 dictionary 只是多佔記憶體，call 的次數不會變少。
2. 真正的條件是 key 要 hashable。tuple 本身 immutable，但如果裡面放了 list，例如 `(1, [2, 3])`，還是不能當 key，會丟出 `TypeError`。

**AI-generated coding challenge title:** 壞掉的樓梯（Broken Staircase）

樓梯有 `n` 階（編號 1 到 n），從地面（第 0 階）出發，每次可以爬 1 階或 2 階，`broken` 裡列出的階不能踩。回傳剛好走到第 `n` 階的走法數量。

- `count_ways(4, [])` → `5`
- `count_ways(4, [2])` → `1`
- `count_ways(5, [3])` → `2`

### 2. My Initial Approach — Before AI Help

**My approach:**

1. 跟 `fib` 一樣：最後一步不是從 `n-1` 上來就是從 `n-2` 上來，所以 `ways(n) = ways(n-1) + ways(n-2)`。
2. 踩到壞掉的階就回傳 0。
3. base case 學 `fib` 的寫法，用 `ways(1) = 1`、`ways(2) = 2`。

### 5. Verification

**My final program:**（見 `w2.py`）

```python
def count_ways(n, broken, memo=None):
    if memo is None:
        memo = {}
        broken = set(broken)

    if n < 0 or n in broken:
        return 0
    if n == 0:
        return 1
    if n in memo:
        return memo[n]

    memo[n] = count_ways(n - 1, broken, memo) + count_ways(n - 2, broken, memo)
    return memo[n]
```
