#### Question 1

**Statement:** `bisect_search2` does not require sorted input, and it can always find the target in `O(log n)` time.

- My answer: False
- Reasoning: The list must be sorted first. For example, when searching for `2` in `[1, 3, 2, 4]`, the middle value might be `3`. If we search the left half because `3 > 2`, we incorrectly discard the right half, even though the target `2` is there.
- AI feedback: This example shows that binary search depends on the list being sorted. Only when the data is sorted, the search range is halved each time, and list indexing is `O(1)`, can the worst-case complexity be analyzed as `O(log n)`.

#### Question 2

**Statement:** The first binary-search implementation cuts the search range in half every time, so its overall time complexity must be `O(log n)`.

- My answer: False
- Reasoning: We must check whether slicing copies data and creates extra cost. Each level copies lists of about `n`, `n/2`, `n/4`, and so on. The total copying cost is `O(n)`, so we cannot consider only the `O(log n)` recursive calls.
- AI feedback: Correct. In the first implementation, list copying dominates the total cost, so the more careful analysis is `O(n)`. The second implementation passes only `low` and `high`, so it can maintain `O(log n)` time complexity.

#### Question 3

**Statement:** For a positive integer `number`, the loop count of `int_to_str` is `floor(log10(number)) + 1`. Although the exact formula contains `+1`, its Big-O complexity can be written as `O(log number)`.

- My answer: True
- Reasoning: The important point is the growth rate, so the `+1` can be ignored. Each `number // 10` removes the rightmost digit, so the loop count equals the number of decimal digits. When `number == 0`, the function returns immediately as a special case.
- AI feedback: Correct. Exact counting and asymptotic notation serve different purposes. Big-O omits constant terms that do not affect the growth rate.

#### Question 4

**Statement:** The iterative and recursive factorial implementations both have `O(n)` time complexity, so their actual performance and memory usage are exactly the same.

- My answer: False
- Reasoning: Recursion requires more memory. The iterative version keeps only a fixed number of variables, so its extra space is `O(1)`. The recursive version keeps about `n` function calls on the call stack, so its stack space is `O(n)`.
- AI feedback: Correct. The two versions have the same time-growth rate, but the recursive version also has function-call and call-stack costs, so their actual resource usage is different.

#### Question 5

**Statement:** If a program has two nested loops, its time complexity must be `O(n^2)`.

- My answer: False
- Reasoning: We must check how many times each loop actually runs. If both loops run `n` times, the complexity is `O(n^2)`. If the outer loop runs `n` times but the inner loop always runs exactly 10 times, the total work is `10n`, which simplifies to `O(n)`.
- AI feedback: Correct. The work counts of nested loops usually multiply, but fixed constants are omitted from Big-O notation.

### 1. Today's challenge

Core concept from today's OCW lecture:

使用二分搜尋縮小已排序資料的搜尋範圍，並用索引表示目前的 `low`、`high`，避免複製 list。

AI-generated coding challenge title:

**Find the first position that is at least the target**

給定一個由小到大排序、可能包含重複值的整數 list `values`，以及整數 `target`。請回傳第一個大於或等於 `target` 的元素索引。如果所有元素都小於 `target`，回傳 `len(values)`。

要求使用不建立子 list 的方法，並讓搜尋時間複雜度維持在 `O(log n)`。

#### Input and output

```text
Input:  一個排序後的整數 list values，以及整數 target
Output: 第一個 values[index] >= target 的 index
```

#### Constraints

- `values` 由小到大排序，可以包含重複值。
- `target` 是整數。
- 空 list 時應回傳 `0`。
- 不可以使用 slicing 建立搜尋中的子 list。

#### Examples


```text

```


The most useful hint/question from AI was:

The counterexample `[1, 3, 3, 3, 5]` with `target = 3` showed that finding a matching middle element does not prove it is the first match.

It helped me realize that:

When `values[mid] >= target`, the answer might be at `mid` or further left. When `values[mid] < target`, all positions up to `mid` can be discarded. If every value is smaller than `target`, the answer is `len(values)`.

### 4. My revision

What did I change, and why?

I changed the proposed approach from returning on equality to finding the leftmost qualifying boundary. The AI-assisted program below uses `low` as the start and `high` as the end of a half-open search range `[low, high)`. It does not create list slices. I have not rewritten the final program independently.

```python
def first_at_least(values, target):
    low = 0
    high = len(values)

    while low < high:
        mid = (low + high) // 2
        if values[mid] < target:
            low = mid + 1
        else:
            high = mid

    return low
```

The range `[low, high)` always contains the first qualifying index if one exists. When `values[mid] < target`, the first qualifying index must be after `mid`, so `low = mid + 1`. Otherwise, `mid` might be the answer, so `high = mid` keeps it in the range. When the range is empty, `low` is the boundary. If no element qualifies, that boundary is `len(values)`.
