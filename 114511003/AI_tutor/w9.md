The final AI-assisted solution sorts by end time from earliest to latest. It accepts a workshop when its start time is at least the end time of the last accepted workshop. I have not rewritten this solution independently.

#### Final AI-assisted program

```python
def max_workshops(workshops):
    # Other input types and bounds follow the stated problem constraints.
    if any(start >= end for start, end in workshops):
        raise ValueError("Each workshop must have start < end")

    ordered = sorted(workshops, key=lambda workshop: workshop[1])
    count = 0
    last_end = None

    for start, end in ordered:
        if last_end is None or start >= last_end:
            count += 1
            last_end = end

    return count
```

`lambda workshop: workshop[1]` returns the end time, so it is the key function. `sorted` uses ascending order by default and creates a new list, preserving the input order. Unlike the lecture's knapsack code, this solution does not use `reverse=True`.

`last_end` stores the end time of the last accepted workshop. It changes only when a workshop is accepted. `None` represents an empty schedule, so the first workshop can be accepted without inventing a starting time. The comparison uses `>=` because intervals that share an endpoint do not overlap.

#### Worked example

For `[(1, 10), (2, 3), (3, 4), (4, 5)]`, sorting by end time gives:

| Workshop | Decision | Count | Last end |
|---|---|---:|---:|
| (2, 3) | Accept as the first workshop | 1 | 3 |
| (3, 4) | Accept because 3 >= 3 | 2 | 4 |
| (4, 5) | Accept because 4 >= 4 | 3 | 5 |
| (1, 10) | Skip because 1 < 5 | 3 | 5 |

The result is 3.

#### Why the solution works

Feasibility: Every accepted workshop starts at or after the previous accepted workshop ends, so the selected workshops never overlap.

Optimality, using an exchange argument: Let G be a workshop with the earliest end time. Take any optimal nonempty schedule and let O be its first workshop. G ends no later than O. Replacing O with G leaves all the later workshops available, because they start at or after O ends and therefore also at or after G ends. Thus an optimal schedule exists that starts with G. The same argument applies to the remaining workshops that start at or after G ends. Repeating it proves that the greedy algorithm achieves the maximum count. Empty input has optimal count 0.

If several workshops share the earliest end time, any of them works for this argument. This proof depends on each workshop contributing the same count of 1. If workshops have different rewards, earliest finish does not generally maximize total reward.

from itertools import combinations


def brute_force_count(workshops):
    # Small-input reference only; not the final algorithm.
    best = 0
    for size in range(len(workshops) + 1):
        for subset in combinations(workshops, size):
            ordered = sorted(subset)  # Sort by start time for overlap checks.
            valid = all(
                ordered[i][1] <= ordered[i + 1][0]
                for i in range(len(ordered) - 1)
            )
            if valid:
                best = max(best, size)
    return best


cases = [
    ([(1, 3), (2, 5), (3, 4), (4, 6)], 3),
    ([(1, 10), (2, 3), (3, 4), (4, 5)], 3),
    ([], 0),
    ([(2, 5)], 1),
    ([(1, 3), (3, 5)], 2),
    ([(1, 5), (2, 4), (3, 6)], 1),
    ([(1, 3), (1, 3), (3, 4)], 2),
    ([(4, 6), (0, 2), (2, 4)], 3),
    ([(0, 4), (4, 8), (3, 5)], 2),
    ([(0, 3), (1, 3), (3, 4)], 2),
]
for workshops, expected in cases:
    before = workshops[:]
    actual = max_workshops(workshops)
    assert actual == expected, (workshops, expected, actual)
    assert workshops == before, "The input list must not change"

for invalid in [[(2, 2)], [(5, 3)]]:
    try:
        max_workshops(invalid)
    except ValueError:
        pass
    else:
        raise AssertionError("Invalid intervals should raise ValueError")

pool = [(start, end) for start in range(4) for end in range(start + 1, 5)]
checked = 0
for size in range(len(pool) + 1):
    for subset in combinations(pool, size):
        workshops = list(reversed(subset))
        assert max_workshops(workshops) == brute_force_count(workshops)
        checked += 1
assert checked == 1024

assert max_workshops([(i, i + 1) for i in range(10000)]) == 10000

Time complexity: Validation takes O(n), sorting takes O(n log n) worst-case time, and the scan takes O(n). The total is O(n log n).

Space complexity: O(n) extra space for the sorted list and sorting workspace. The scan uses O(1) additional space.

The brute-force reference is used only on small inputs. Its worst-case time is O(n log n × 2^n), since it sorts each candidate subset. It uses O(n) additional space by generating one candidate at a time.
