#### Question 1

```python
def linear_search(L, e):
    found = False
    for i in range(len(L)):

```

If `e` is at the first position, the best-case time complexity of this function is `O(1)`.

My answer: False

#### Question 2

Statement:

If a list is sorted in ascending order, the search can safely return `False` when the current element is greater than the target.

My answer: True

Reason: Because the list is sorted, every element after the current element will be at least as large as the current element. If the current element is already greater than the target, the target cannot appear later in the list.

#### Question 3

Statement:

If a list is sorted, searching it always has `O(log n)` time complexity.

My first answer: True

After discussing the difference between a sorted list and a binary search, I revised my answer to False.

Reason: Sorting alone does not make a search logarithmic. If the program still checks the list from left to right, the target may be at the last position or may not exist, so the worst-case time complexity is still `O(n)`. Binary search is `O(log n)` because it cuts the remaining search range in half at each step.

#### Question 4

Statement:

```python
def isSubset(L1, L2):
    for e1 in L1:
        matched = False
        for e2 in L2:
            if e1 == e2:
                matched = True
                break
        if not matched:
            return False
    return True
```

If `len(L1) = n` and `len(L2) = m`, the worst-case time complexity is `O(n + m)`.

My answer: False

Reason: For every element in `L1`, the function may scan all elements in `L2`. The worst-case number of comparisons is therefore `n * m`, so the time complexity is `O(nm)`. If `n` and `m` are about the same size, this can be written as `O(n^2)`.

#### Question 5

Statement:

```python
for i in range(n):

```

The time complexity of this code is `O(n^2)`.

My answer: False

Reason: The inner loop always runs exactly 10 times, and 10 is a constant. The total number of operations is `10n`, which is simplified to `O(n)`.

#### Problem statement

給定一個整數 list `values` 和一個整數 `target`，請判斷 list 中是否存在兩個不同位置的元素，使它們的總和等於 `target`。

如果存在，回傳 `True`；否則回傳 `False`。兩個元素必須來自不同的索引。

#### Input and output

- Input: 一個整數 list `values` 和一個整數 `target`。
- Output: 如果存在符合條件的兩個元素，回傳 `True`，否則回傳 `False`。

#### Constraints

- `values` 可以是空 list。
- list 中可能有重複的數字。
- 兩個元素必須來自不同索引。
- 使用 list、for 迴圈與條件判斷。
- 本題不使用 `set`。

#### Examples

Output: True

### 4. My revision

Yes, I changed my approach.

我將內層迴圈改成從 `i + 1` 開始，而不是從 0 開始。這樣可以避免使用同一個索引的元素和自己相加，也可以避免重複檢查相同的配對，例如 `(values[0], values[1])` 和 `(values[1], values[0])`。

### 5. My final program

```python
def has_pair_sum(values, target):
    for i in range(len(values)):
        for j in range(i + 1, len(values)):
            if values[i] + values[j] == target:
                return True
    return False
```

### 7. Why my solution works

外層迴圈選取第一個元素，內層迴圈只檢查它後面的元素。這樣每一組配對只會被檢查一次，也不會讓同一個索引和自己配對。

只要找到一組總和等於 `target` 的配對，函式就回傳 `True`。如果所有配對都不符合，最後回傳 `False`。

### 8. Time and space complexity

令 `n` 為 `values` 的長度。

- Best-case time complexity: `O(1)`，第一組配對就符合條件。
- Worst-case time complexity: `O(n^2)`，需要檢查所有元素配對。
- Extra space complexity: `O(1)`，只使用固定數量的變數。
