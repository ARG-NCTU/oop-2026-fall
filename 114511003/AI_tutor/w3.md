#### Question 1

Statement:

> If a program runs without raising an exception, its output must be correct.

Answer: False

Reason: A program can run successfully and still contain a logic error. Testing must compare the actual output with the expected output from the specification.

#### Question 2

Statement:

> Regression testing adds tests for bugs that have already been found and fixed.

Answer: True

Reason: A regression test checks that a previously fixed error does not return after later changes to the program.

#### Question 3

Statement:

> Black-box testing depends on the internal implementation of the function.

Answer: False

Reason: Black-box testing uses the function specification, expected input-output behavior, natural partitions, and boundary cases. It does not require looking at the source code, so the tests can often be reused after the implementation changes.

#### Question 4

Statement:

> The `finally` block is used for code that should run after `try`, whether or not an exception occurs.

Answer: True

Reason: `finally` is useful for cleanup work such as closing a file. It runs after the related `try`, `except`, and `else` clauses, including when the earlier block executes `return`, `break`, or `continue`.

#### Question 5

Statement:

> Assertions are the best replacement for all user-input validation.

Answer: False

Reason: Assertions are mainly for checking internal assumptions that should be true if the program is correct. User input can be invalid during normal use, so the program should usually raise and handle a suitable exception such as `ValueError` or `TypeError`.

### 5. My final program

```python
def average_grades(grades):
    if not isinstance(grades, list):
        raise TypeError("grades must be a list")

    if len(grades) == 0:
        raise ValueError("grades must not be empty")

    for grade in grades:
        if not isinstance(grade, (int, float)):
            raise TypeError("each grade must be an int or float")

    return sum(grades) / len(grades)
```

這個函式把使用者可能提供的錯誤資料當成例外處理，而不是使用 assertion。因為空 list 或錯誤型別可能是外部輸入的正常錯誤情況，呼叫者可以捕捉例外並顯示訊息。

### 6. Verification

測試程式：

```python
def check_average_grades():
    assert average_grades([80, 70, 90]) == 80.0
    assert average_grades([5]) == 5.0
    assert average_grades([1.5, 2.5]) == 2.0

    original = [80, 70, 90]
    average_grades(original)
    assert original == [80, 70, 90]

    try:
        average_grades([])
    except ValueError:
        pass
    else:
        raise AssertionError("empty grades should raise ValueError")

    try:
        average_grades([80, "70"])
    except TypeError:
        pass
    else:
        raise AssertionError("invalid grade type should raise TypeError")
```
