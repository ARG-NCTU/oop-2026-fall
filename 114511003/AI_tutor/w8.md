#### Question 3

Reason: For eight elements, the merge levels process `4 × 2`, `2 × 4`, and `1 × 8` elements. Each level handles all eight elements. Generally, each of about `log₂ n` levels takes `O(n)` work, giving `O(n log n)` total time.

#### Question 4

Statement: If bubble sort completes a full pass without swapping any elements, the list is sorted, so the algorithm can stop.

My first answer was False because I was thinking about an implementation that might run only once or lack a stopping check. After discussing what a full pass proves, I revised my answer to True.

Reason: A full pass compares every adjacent pair. If no pair needs a swap, all adjacent pairs are in order, so the entire list is sorted. An implementation needs to check the `swapped` flag to stop at that point.

Reason: One linear search takes `O(n)` worst-case time. Sorting once with merge sort and then searching takes `O(n log n + log n)` time. Sorting becomes more useful when the same sorted list supports many searches.

### 5. Verification

My final program:

```python
def find_first_at_least(values: list[int], target: int) -> int:
    low = 0
    high = len(values) - 1
    ans = len(values)

    while low <= high:
        mid = (low + high) // 2

        if values[mid] >= target:
            ans = mid
            high = mid - 1
        else:
            low = mid + 1

    return ans


def count_scores_in_range(scores: list[int], low: int, high: int) -> int:
    left_idx = find_first_at_least(scores, low)
    right_idx = find_first_at_least(scores, high + 1)
    return right_idx - left_idx
```
