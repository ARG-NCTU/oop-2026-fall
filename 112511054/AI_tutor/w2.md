### 題目與 AI 參考解答

#### 第 1 題：commit 與 push

**題目：** 只在本機成功執行 `git commit`，即使沒有執行 `git push`，助教也能在 GitHub 課程 repo 看到這次提交的檔案。

**答案：錯。**

`git commit` 在本機儲存庫建立版本紀錄，並不會自動傳送到 GitHub。必須成功把包含該 commit 的分支推送到指定遠端，助教才看得到那次提交。`git status` 可以檢查本機狀態，GitHub 網頁則可以確認遠端是否收到檔案。

#### 第 2 題：暫存區保存的內容

**題目：** 先把檔案內容 A 用 `git add` 放進暫存區，再把工作目錄中的檔案改成 B。如果沒有重新 `git add`，直接執行一般的 `git commit -m "update"`，這個檔案被提交的仍是 A。

**答案：對。**

暫存區保存的是準備納入下一次提交的內容。工作目錄後來改成 B，不會自動更新已暫存的 A。要把 B 納入這次提交，需要重新 `git add`。提交前可用 `git diff` 查看尚未暫存的修改，用 `git diff --cached` 查看即將提交的內容。

#### 第 3 題：Git 身分與遠端權限

**題目：** 只要把 `git config user.name` 和 `user.email` 設成課程成員的帳號與信箱，就會取得課程 repo 的 push 權限。

**答案：錯。**

這些設定是提交紀錄中的作者資訊，不是 GitHub 登入憑證，也不會授予權限。推送需要通過 GitHub 的身分驗證，並且該帳號具有目標 repo 的寫入權限。依課程公告，收到邀請後還需要接受邀請。

#### 第 4 題：Fork 與 Clone

**題目：** `git clone` 和 GitHub 的 Fork 完全相同，都會在自己的 GitHub 帳號底下建立一份新的 repo。

**答案：錯。**

Clone 是把既有儲存庫複製到本機，包含檔案及版本歷史；它不會自動在自己的 GitHub 帳號下建立 repo。Fork 則是在 GitHub 上建立一份與原專案具有關聯的儲存庫。可以先 Fork，再把自己的 fork Clone 到本機。

#### 第 5 題：SSH 金鑰

**題目：** 設定 GitHub SSH 連線時，應上傳 `id_ed25519.pub` 公鑰，並把沒有 `.pub` 的私鑰保留在自己的電腦。

**答案：對。**

公鑰可以交給 GitHub，私鑰用來證明連線者持有配對金鑰，不能公開。教材用 `ssh -T git@github.com` 驗證 SSH 身分驗證是否成功；成功驗證仍不等於具有每個 repo 的寫入權限。

### ② My Misconception

- Before（常見誤解參考）：以為存檔或 commit 就等於交到 GitHub，也以為設定 Git 作者信箱就能取得遠端權限。
- Now（正確觀念參考）：工作目錄、暫存區、本機儲存庫與遠端儲存庫是不同位置。add 選定要提交的內容，commit 建立本機版本，push 才把版本送到遠端。作者資訊與 GitHub 身分驗證、repo 權限也要分開理解。
