### ② My Misconception

- Before — 常見誤解：以為函式參數一律是副本；以為 `private` 本身就會檢查數值合法性；以為同名函式一定會有多型行為；以為 `delete` 與 `delete[]` 可以互換。

## Part B：LeetCode-style Lecture Code Transfer

### 1. Today’s Challenge

- Core concept from today’s lecture：透過共同基底類別呼叫不同子類別行為；使用建構子初始化私有資料；透過參考修改值；正確管理動態物件及陣列。
- AI-generated coding challenge title：多型任務排程後的剩餘工作量。
- 來源說明：此挑戰依本次 W5 C++ 教材設計；沒有另行提供 OCW 程式來源。

#### 題目敘述

有 `n` 個任務，各有非負的初始工作量。類型 1 的任務每回合最多完成 1 單位工作；類型 2 每回合最多完成 2 單位工作。所有任務都會被安排執行 `k` 回合。工作量已經歸零的任務保持為零，不能變成負數。

求執行 `k` 回合後，所有任務剩餘工作量的總和。

為練習本次教材，實作應建立抽象基底類別及兩個子類別，透過基底指標呼叫 `Step()`。工作量使用私有成員儲存；另外使用參考函式把負值歸零。動態配置的任務與指標陣列都要正確釋放。

#### 輸入、輸出與限制

- 第一行輸入兩個整數 `n k`。
- 接下來 `n` 行，每行輸入 `type work`，代表任務類型及初始工作量。
- 輸出一個整數：最終剩餘工作量總和。
- `0 <= n <= 1000`；`0 <= k <= 1000`；`type` 為 1 或 2；`0 <= work <= 1000`。

範例 1：

```text
輸入
3 2
1 5
2 5
1 1

輸出
4
```

兩回合後的工作量分別為 3、1、0，總和為 4。

範例 2：

```text
輸入
2 0
1 3
2 4

輸出
7
```

沒有執行任何回合，工作量維持原值。

範例 3：

```text
輸入
2 3
1 2
2 3

輸出
0
```

任務都已完成，剩餘工作量保持為零。

#### 正確性與複雜度

初始時，每個物件保存輸入的工作量。每一回合，類型 1 減去 1，類型 2 減去 2，再把負數歸零。因此每一步都符合題目的消耗規則，也讓完成任務維持為零。經過 `k` 回合後，把每個任務的剩餘工作量加總，即為所求。

- 時間複雜度：`O(nk + n)`；初始化與加總各需走訪一次全部任務，排程走訪 `k` 次。
- 額外空間複雜度：`O(n)`；保存 `n` 個指標與 `n` 個任務物件。
- 概念轉移：教材的 `MyApp` 示範單一子類別的虛擬函式；新題用兩種子類別及相同排程迴圈，將多型用於不同的工作量更新行為。
