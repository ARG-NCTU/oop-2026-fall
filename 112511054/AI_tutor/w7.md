### 題目與解答

#### 第 1 題：PWT 是否代表完全覆蓋

**題目：** 如果朝北行為的 pwt 高於朝東行為，Helm 就只考慮朝北行為，完全忽略朝東行為。

**答案：錯。**

本週教材的整合方式是將各 active 行為的效用乘上對應 pwt，再加總求最佳決策。權重較大表示該分數在總效用中較有影響力，不代表直接取消其他正權重行為。最後結果還取決於所有候選解上的效用分布，而不是只比較權重大小。

#### 第 2 題：所有權重等比縮放

**題目：** 在候選集合與效用函數不變、以精確算術計算的前提下，把所有參與加總的權重同乘一個正數，最佳解的集合不變。

**答案：對。**

原目標為 `F(x)=Σ w_i U_i(x)`，縮放後為 `cF(x)`。當 c>0，任何兩個候選的大小關係和平手關係都不變，因此最大值的位置不變。必須縮放所有參與的權重；只改其中兩個而保留第三個不變，不適用這個結論。乘以 0 或負數也不適用。

#### 第 3 題：等權重與折衷方向

**題目：** 朝東與朝北的權重都是 100，因此最後選到的航向一定是兩個方向的平均值 45°。

**答案：錯。**

Helm 是加總效用後求最大值，不是直接平均航向。結果受到兩個效用函數的形狀、候選離散化，以及航向與速度共同決策影響。簡報固定速度下的分數表是示意；2026-10-19 原實驗 Case 1 的短時觀察目標航向為 32°，也不能把這個數字推廣成所有等權重情況的固定答案。

#### 第 4 題：偏好航向是否保證前進

**題目：** 只要 BHV_ConstantHeading 設定 heading=0，且該行為正在執行，船就一定會朝北以非零速度前進。

**答案：錯。**

航向偏好不等於航速要求。原始 Case 3 在東／北權重 30／100 下，Helm 處於 DRIVE，但選到目標速度 0，船停在起點。保留這兩個權重並加入適當的 BHV_ConstantSpeed 後，既有測試選到 2.0 m/s 並實際移動。這是新增速度效用改變了最佳解，不是兩股物理推力互相抵銷後又被修好。

#### 第 5 題：決策空間

**題目：** 本週設定使用 360 個航向與 41 個速度選項，因此航向與速度的組合共有 14760 個；最佳化時不能只看航向分數就保證得到同一結果。

**答案：對。**

組合數為 `360 × 41 = 14760`。只觀察固定速度下幾個航向的分數，相當於只看整個決策空間的一部分；若效用同時依賴航向與速度，其他速度可能提供更好的總分。因此設定中的航點 speed 並不能直接當作最終速度的硬性限制。

### ② My Misconception

- Before（常見誤解）：以為 PWT 最大的行為會完全接管；以為兩個等權重方向應直接取平均；以為指定航向就同時指定了前進速度。
- Now（觀念整理）：PWT 是效用的加權係數，最終決策來自完整候選空間上的加權總分。航向與速度可以共同影響效用，偏好某個方向仍可能得到零速度。

## Part B: LeetCode-style Lecture Code Transfer

### 1. Today’s Challenge

- Core concept from today’s lecture：各 active 行為提供候選決策的效用，乘上各自權重後加總，選擇最佳航向與速度組合。
- Coding challenge title：安全候選的多行為加權決策器。
- 轉移來源：簡報第 5～6 頁的決策空間與加權總分，以及拔河任務的多行為配置。本題使用外部給定的效用表與可用旗標，新增不可用候選過濾與確定的平手規則，並非直接複製原始兩行為實驗。
- 題目定位：獨立的 C++ 有限候選最佳化題，不實作 IvP 分段函數求解器、ROC 或船舶控制。可用旗標及以下平手規則是本題規格，不宣稱真實 Helm 採用相同處理方式。

#### Problem statement

給定 n 個不同的 `(heading, speed_index)` 候選與 m 個行為。第 j 個行為的權重為 w_j；候選 i 對該行為的效用為 u_ij。每個候選另有 allowed，代表外部檢查判定是否可用。

對 allowed=1 的候選計算：

```text
score(i) = w_1*u_i1 + w_2*u_i2 + ... + w_m*u_im
```

選總分最高者；若同分，先選 speed_index 較小者；速度仍相同，再選 heading 較小者。沒有可用候選時輸出 -1。

allowed=0 是本題的排除條件，不是較低效用；即使它的分數最高，也不能被選取。權重 0 的行為不貢獻總分。速度索引 0 合法，代表停船選項。

#### Input/output specification and constraints

- 第一行為 `n m`；第二行為 m 個權重。
- 接下來 n 行各為 `heading speed_index allowed u_1 ... u_m`。
- heading 是 0～359 的整數角度；speed_index 是 0～40 的整數索引，對應 `speed_index / 10` m/s。
- 每個 `(heading, speed_index)` 組合最多出現一次，資料格式保證正確。
- `0 <= n <= 14760`；`1 <= m <= 20`。
- `0 <= w_j <= 1000000000`；`0 <= u_ij <= 100`；allowed 為 0 或 1。
- 有解時輸出 `heading speed_index score`；無解時輸出 `-1`。
- 最大總分為 `20 × 1000000000 × 100 = 2000000000000`，必須使用足夠寬的整數型別。

範例 1：

```text
輸入
3 2
2 1
0 20 1 100 0
45 20 1 90 80
90 20 1 0 100
輸出
45 20 260
```

三個候選總分為 200、260、100。雖然第一個行為權重最大，最後仍選雙方都能接受的折衷候選。

範例 2：

```text
輸入
2 2
1 1
0 0 0 100 100
90 10 1 60 60
輸出
90 10 120
```

總分 200 的候選不可用，因此選總分 120 的可用候選。

範例 3：

```text
輸入
3 1
0
90 20 1 100
180 10 1 50
0 10 1 0
輸出
0 10 0
```

全部權重為 0 時都同分，先比較速度，再比較航向；不是選取原始效用最高的候選。

#### Why the solution works and complexity

處理任何候選前，found 表示目前是否已有可用候選。每一列的累加計算符合目標公式；若候選不可用，就不參與排名。對可用候選依分數較大、同分速度較小、同速航向較小的順序比較，因此處理每個前綴後，保留的都是此前綴最佳候選。全部處理完後即為全域最佳；found 仍為 false 時，才輸出 -1。

讀取權重需 `O(m)`，n 個候選各讀 m 個效用需 `O(nm)`，總時間為 `O(m+nm)`。實作使用固定 20 格權重陣列與少量狀態，不保留全部候選；在題目給定上限下額外空間為 `O(1)`，其中最多保存 m 個權重。
