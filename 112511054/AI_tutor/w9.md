## Part B: LeetCode-style Lecture Code Transfer

### 1. Today’s Challenge

- Core concept：把 C++ 類別的狀態封裝與 vector 處理，透過 pybind11 提供給 Python；以例外表達錯誤。
- Coding challenge title：有容量限制的批次裝載器。
- 轉移來源：原 Lab 的 `GradeBook`、list／vector 轉換與例外。本題改成有序裝載、跨批次狀態及無效批次的原子性，並非重做成績平均。

#### Problem statement

實作 C++ `CargoLoader(capacity)`，並綁定給 Python。

`add_batch(weights)` 先驗證整批重量，再依索引順序嘗試裝載。放得下就裝載並回傳該批的索引；放不下就跳過，繼續處理後面的物品。已裝載的重量與件數保留至下一批。這是固定順序的模擬規則，不求解背包問題，也不保證最多件數。

提供 `load()`、`remaining()`、`count()` 與 `clear()`；clear 清空貨物但保留容量。任一重量不合法時拋出 `std::invalid_argument`，Python 應收到 `ValueError`，而且整批不能改變物件狀態。容量不合法也拋出同一例外。各物件狀態必須獨立，輸入 list 不被修改。

#### Input/output specification and constraints

- 以 Python 方法呼叫輸入，`add_batch` 回傳接受索引的 list，查詢方法回傳整數。
- `1 <= capacity <= 10^12`；`1 <= weight <= 10^12`；整數以 C++ 64 位元型別儲存。
- 每批 `0 <= len(weights) <= 100000`，超過上限視為不合法批次；整段測試累計處理不超過一百萬件。
- 空批合法，回傳空 list；索引以每批 0 開始。輸入為可轉換成 64 位元整數的 list，超出可轉換範圍不屬本題資料。

| 範例 | 呼叫 | 預期結果 |
| --- | --- | --- |
| 1 | `x = CargoLoader(10); x.add_batch([6, 5, 4])` | `[0, 2]`；load=10、count=2。跳過 5 後仍能放入 4。 |
| 2 | `x = CargoLoader(8); x.add_batch([3]); x.add_batch([6, 2, 3])` | 第一批 `[0]`，第二批 `[1, 2]`；load=8、count=3。 |
| 3 | `x = CargoLoader(5); x.add_batch([2, 0, 1])` | `ValueError`；load=0、count=0。不能先裝入 2 才發現錯誤。 |

#### Why the solution works and complexity

驗證階段不修改成員，因此無效批次直接失敗且狀態不變。對合法批次，以目前剩餘容量判斷每件；接受時同步更新總重、件數與索引，拒絕時三者均不變。逐項處理後，狀態恰好符合規定的有序裝載過程，且總重不會超過容量。clear 將兩個計數恢復為零。

n 件批次的驗證與裝載各為 `O(n)`，合計時間 `O(n)`；C++ 物件額外狀態為 `O(1)`。回傳索引及 Python／vector 轉換使用 `O(n)` 空間，不能因參數為 `const &` 就宣稱整個呼叫是常數空間。
