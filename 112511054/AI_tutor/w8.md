## Part B: LeetCode-style Lecture Code Transfer

### 1. Today’s Challenge

- Core concept：C++ 封裝、基底參考的虛擬呼叫、事件驅動狀態變更，以及依規格設計測試。
- Coding challenge title：可復原的任務事件處理器。
- 轉移來源：W4／W5 的電量封裝與多型、W6 的消息狀態機，加入 W2 狀態版本的概念並用 W3 的邊界測試方式驗證。這是獨立的記憶體內狀態練習，不實作 Git 儲存庫或 MOOS 通訊。

#### Problem statement

載具有固定容量 capacity、目前電量 energy、已完成任務數 completed，以及有效狀態變更的歷史。初始電量為 initial、completed=0、歷史為空。依序處理事件：

| 事件 | 規則 |
| --- | --- |
| `CHARGE x` | 電量增加 x，但最高為 capacity。只有電量確實增加時才保存變更前的完整狀態。 |
| `RUN x` | 電量至少為 x 時成功：保存原狀態、扣除 x、completed 加一；電量不足時整個事件忽略。x=0 仍會增加 completed，因此必須保存歷史。 |
| `UNDO` | 歷史非空時恢復最近一次有效變更前的 energy 與 completed，並移除該筆歷史；空歷史時忽略。UNDO 本身不加入歷史，沒有 REDO。 |

失敗任務、無效果充電都不新增歷史，因此 UNDO 不是單純撤銷上一行輸入。撤銷後的新事件形成新的歷史，不保留已撤銷分支。

結構要求：用 Mission 類別封裝資料；定義抽象 Event 的 `apply(Mission&) const`，由 ChargeEvent、RunEvent、UndoEvent 覆寫。共用 dispatch 函式經由 `const Event&` 呼叫，不直接依子類型執行方法。

#### Input/output specification and constraints

- 第一行 `capacity initial n`；接著 n 行為上述事件。
- 輸出一行 `energy completed history_size`。
- `1 <= capacity <= 10^9`；`0 <= initial <= capacity`；`0 <= n <= 100000`；`0 <= x <= 10^9`。
- 輸入保證符合格式與範圍；所有狀態用 64 位元整數處理。

範例 1：

```text
輸入
10 4 3
CHARGE 9
RUN 6
UNDO
輸出
10 0 1
```

充電先被上限截為 10；RUN 後為 4、完成數為 1；UNDO 恢復到充電後的 10、0，留下充電的歷史一筆。

範例 2：

```text
輸入
5 2 3
RUN 3
CHARGE 0
UNDO
輸出
2 0 0
```

失敗任務及零充電都沒有有效變更，因此 UNDO 也沒有可恢復的狀態。

範例 3：

```text
輸入
5 0 2
RUN 0
UNDO
輸出
0 0 0
```

RUN 0 曾將完成數變成 1，UNDO 必須把它還原。

#### Why the solution works and complexity

每次事件後保持：目前狀態等於依規則執行未撤銷的有效事件所得結果，而 history 由舊到新保存各有效變更前的完整狀態。有效充電或任務先存原狀態再變更，因此維持不變量；失敗或無效果事件不修改任何狀態；UNDO 取回最近快照並移除歷史，所以恢復上一有效狀態。兩個欄位一起還原，完成數與電量不會分離。

n 個事件總時間為 `O(n)`：vector 的 push_back 為攤銷常數時間，取末筆與 pop_back 為常數時間。歷史最多 n 筆，因此額外空間 `O(n)`。只保存最後狀態不能支援任意多次 UNDO；慢速重播只用於小案例的獨立參考模型，不是提交程式的效能。
