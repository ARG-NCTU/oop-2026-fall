## ② My Misconception

### Before: I thought…

I tended to identify complexity mainly from the visible recursive structure. For example, I assumed that binary search must always be `O(log n)` because it cuts the search range in half, and I thought exponential recursion required multiple recursive calls at every level.

### Now: I understand…

The recursive structure alone is not enough to determine the total complexity. I also need to include the work performed at each recursive level.

A binary search implementation that uses list slicing performs additional copying. Even though the number of recursive levels is logarithmic, the total copying cost can make the implementation `O(n)`. Using indices such as `low` and `high` avoids that copying cost and gives the expected `O(log n)` behavior.

I also understand that multiple recursive calls are a common sign of exponential complexity, but they are not required. The power-set algorithm has only one recursive call at each level, yet the number of subsets doubles as the input grows, so the work required to construct the result is still exponential.
