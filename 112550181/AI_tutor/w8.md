## ② My Misconception

### Before: I thought…

I did not have a major misconception that required revising an answer, but I mainly thought about the complexity of a single search or sort operation by itself.

### Now: I understand…

The best strategy can depend on how many times an operation will be repeated. For a single search on an unsorted list, doing a linear search can be better than first paying the cost to sort the list. However, if the same list will be searched many times, the one-time sorting cost can be amortized across those searches.

With merge sort and binary search, the total cost for `k` searches is `O(n log n + k log n)`, compared with `O(kn)` for repeatedly using linear search. When `k` becomes large, the one-time sorting cost becomes less important per search.

I also understand why merge sort is `O(n log n)`: there are `O(log n)` levels of division, and each level performs `O(n)` total work while merging.
