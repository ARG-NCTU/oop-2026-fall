### ② My Misconception

**Before: I thought…**

我曾經把 `break` 理解成「程式到這裡就結束」，所以看到兩層迴圈中有 `break`，會直覺認為兩層都不會再繼續執行。

**Now: I understand…**

`break` 只會離開它所在的那一層迴圈。比如外層跑三次、內層找到符合條件的元素就 `break`，外層還是會繼續處理下一輪。因此要追蹤程式流程，不能只看有沒有寫 `break`，還要看它位於哪個縮排層級。

### 1. Today’s Challenge

**Core concept from today’s OCW lecture:**

**AI-generated coding challenge title:** 找出最早連續出現的指定字元（First Consecutive Target Run）

### Problem Statement

給定一個字串 `s`、單一字元 `target` 和正整數 `k`，找出**第一段連續至少 k 個 target** 的起始索引。如果不存在，回傳 -1。大小寫不同視為不同字元。只需回傳最早符合的索引，不必回傳整段字串。

### Input / Output Specification

- 輸入：`s` 為字串、`target` 為長度 1 的字串、`k` 為正整數。
- 輸出：最早連續 k 個目標字元的 0-based 起始索引，或 `-1`。
- 函式介面：`first_run(s, target, k)`。

### Constraints

- `0 ≤ len(s) ≤ 10000`。
- `len(target) = 1`，`1 ≤ k ≤ 10000`。
- 不修改原字串。

### Examples

**Example 1**

```text
Input:  s="abxxxxy", target="x", k=3
Output: 2
```

**Example 2**

```text
Input:  s="AaaA", target="a", k=3
Output: -1
```

**Example 3**

```text
Input:  s="bbbb", target="b", k=1
Output: 0
```

### 2. My Initial Approach — Before AI Help

最直接可以從每一個索引開始，往後檢查接下來 k 個位置是否都是目標字元。不過這樣每次又從頭比較，遇到很長的連續區間時會重複做很多工作。

**Did you ask the AI Tutor for help?**

**The most useful hint/question from AI was:**

是否能在一次走訪字串時，記住目前連續相同字元已出現幾次？什麼時候應該把計數歸零？

**It helped me realize that:**

只要維護 `count`，遇到目標字元就加一，不是目標字元就歸零；第一次累計到 k 時，起點就是目前索引減 k 加一。

### 4. My Revision

- 將從每個位置重新檢查 k 次的構想，改為只掃描字串一遍。
- 新增 `count` 紀錄目前連續匹配長度。
- 到達 k 時直接 `return`，因此一定取得最早符合的位置。

### Final Program

```python
def first_run(s, target, k):
    count = 0
    for i in range(len(s)):
        if s[i] == target:
            count += 1
        else:
            count = 0
        if count >= k:
            return i - k + 1
    return -1
```

### Why the Solution Works

當掃描到索引 i 時，`count` 恰好是以 i 結尾的連續目標字元長度；遇到其他字元會歸零。第一次出現 `count >= k` 的位置，便是最早能湊成連續 k 個目標字元的結尾，故 `i-k+1` 為最早合法起點。若掃描完仍未達 k，代表不存在符合區段。

### Complexity

令 n = `len(s)`。最壞情況掃描所有字元一次，每次比較與更新是固定成本，因此時間 **O(n)**；只用計數器與索引，額外空間 **O(1)**。
